# 介面改版：新擬態（Neumorphism / Soft UI）

本輪把原生版從「近黑底色 + 描邊卡片 + 強調色塊」換成**新擬態**：全站只有一塊石墨材質，
層次由「凸起 / 凹陷」和柔光（右下深投影 + 左上淺高光）表達。
改動只發生在 UI 層；內容協議、請求籤名、播放與解密程式碼一行未動。

> 上一版（極光 TV 式排版）的說明保留在本檔案末尾的「上一版設計」一節，兩者的排版結構是繼承關係，
> 本輪換掉的是**材質與形狀語言**，不是資訊架構。
>
> **色板於 2026-10-07 二次改版**：材質從灰藍退成中性石墨，強調色從高飽和品牌藍 `#5980FF`
> 換成香檳金 `#DFB77C`，選中態從「染色底」改成「抬面 + 金環 + 金字」。原因見
> [第 2.1 節](#21-色板改版2026-10-07石墨--香檳金)；結構、柔光實現、按鈕規範一條未變。
>
> **主題於 2026-10-07 三次改版**：**選框不再有任何顏色**——焦點與選中都不再畫強調色細環、
> 也不再用強調色寫字（焦點靠「打亮」、選中靠「按進去」），並且材質本身變成可在
> **設定 → 主題外觀** 裡切換的十四套（經典淺灰 / 優雅奶白 / 深邃暗調 / 高階柔冷 +
> 瓷白 / 月岩灰 / 象牙沙 / 銀鼠尾草 / 藍霧 / 香檳絲綢 / 灰霧玫瑰 / 蒼巖橄欖 / 石墨 / 午夜藍）。
> 原因與派生規則見 [第 2.2 節](#22-主題改版2026-10-07十四套材質--去掉選框的顏色)；
> 結構、柔光實現、按鈕規範、焦點餘量規則一條未變。

## 1. 為什麼新擬態在電視上要改三個地方

教科書式的新擬態是「底板與控制元件同色，只靠雙向投影分層」。直接搬到電視上會踩三個坑：

| 坑 | 後果 | 本專案的處理 |
| --- | --- | --- |
| 同色 = 沒有對比 | 3 米外看不清哪裡是按鈕、哪裡是背景 | 材質分三檔明度（底色 / 凸起面 / 凹陷面），差值約 3%，投影仍然承擔主要層次 |
| 投影必須畫到控制元件邊界之外 | 與滾動容器的裁剪規則打架：要麼描邊被切掉，要麼卡片蓋住頁頭 | 每個控制元件四周留 **柔光帶**（自己的 padding），投影與高光全部畫在控制元件邊界內 |
| 實時模糊太貴 | `setShadowLayer` 在硬體加速畫布上對形狀無效；`RenderEffect` 要 API 31 | 柔光**預渲染成半解析度點陣圖**，按尺寸共享 LRU 快取，每幀只畫一張圖 |

## 2. 設計令牌（`TvStyle.kt`）

下表是**深邃暗調**（預設主題）的實際取值。除幾何與「播放介面」那一組之外，
所有顏色令牌都不是寫死的常量，而是從當前主題的三個色值派生出來的（見
[第 2.2 節](#22-主題改版2026-10-07十四套材質--去掉選框的顏色)）：
換主題只換色值，幾何、圓角、柔光帶、按鈕檔位一件都不動。

| 類別 | 取值 | 用途 |
| --- | --- | --- |
| 底色 `background` | `#2E3238` | 頁面底板，也是柔光的基準色（= 主題的「背景與元素底色」） |
| 凸起面 `surface` | 底色 → 亮部陰影色 45% | 按鈕、卡片、設定項的常態 |
| 抬升面 `surfaceHigh` | 底色 → 亮部陰影色 72% | 焦點容器、設定分組、**抬一檔的選中態** |
| 凹陷面 `well` | 底色 → 暗部陰影色 45% | 搜尋框、海報井、**按進去的選中態** |
| 深凹槽 `wellDeep` | 底色 → 暗部陰影色 72% | 進度條軌道、禁用態 |
| 深投影 `shadowDark` | 暗部陰影色，深色主題 62% / 淺色 72% | 右下，偏移約 `0.36 × 柔光带` |
| 淺高光 `shadowLight` | 亮部陰影色，同一檔強度 | 左上，偏移約 `0.32 × 柔光带` |
| 內陰影 | `innerDark` 暗部色 / `innerLight` 亮部色 | 凹陷槽的左上深、右下亮（淺色主題的配方更重，見 2.2） |
| 焦點面 `lit` | `#F0EAE0`（暖白） | 焦點態與主操作：整個材質裡最亮的一檔 |
| 亮面板上的字 `onLit` | `#1A1612`（暖近黑） | 焦點 / 主操作按鈕的字色 |
| 亮面板柔光 `litGlow` | 焦點面的 20%（深色）/ 35%（淺色） | 亮面板外的一圈光暈，**焦點唯一的「線」** |
| 強調 `accent` | `#DFB77C` | **只做線與小色塊**：進度條、名次星標。**不畫任何選框** |
| 按進去的選中面 `selectedWell` | = `well` | 開關、選項、設定項、主題行的選中態（`INSET`） |
| 抬一檔的選中面 `selectedFace` | = `surfaceHigh` | 網格當前集、當前頁圖示（它們周圍已經是凹的，再凹分不清） |
| 提示色 `tips` | `#FFC24B` | 只做小色塊：評分星標、榜單前三 |
| 文字 | 文字基色的 100% / 84% / 70% / 62% | 標題 / 區塊標題 / 正文 / 輔助（淺色主題是深墨，深色主題是暖白） |
| 播放介面 | `playerText` / `playerDim` / `playerLine` | 壓在影片上的字與線，**永遠暖白，不跟主題** |
| 圓角 | 卡片 12–14dp、膠囊 26dp、彈窗 24dp | 全站只此三檔，整體比上一版放大一倍 |
| 柔光帶 | 控制元件 6dp、大面板 10dp | `SOFT_BAND` / `SOFT_BAND_LARGE` |
| 焦點 | 放大 1.05、最亮的 `lit` 面板 + `litGlow` 光暈 + `onLit` 字 | **沒有細環**；不做位移 |
| 選中 | 按進去（`well` + `INSET`）或抬一檔（`selectedFace` + 更深的柔光） | **沒有細環、沒有強調色文字** |

### 2.1 色板改版（2026-10-07）：石墨 + 香檳金

上線後收到的問題很具體：**「邊框顏色是藍色，太醜了，和整體風格完全不搭；選中的選項也是藍色」**。
指向的是兩處：海報卡焦點那圈 3dp 的品牌藍描邊，和播放設定面板裡「720P / 1.25×」這類選中膠囊。

#### 診斷：問題不在藍，在「唯一一塊高飽和色」

舊色板是「灰藍材質 `#1F232B`（HSV 飽和 28%）+ 品牌藍 `#5980FF`（飽和 100%）」。
頁面裡所有東西的明度差只有 3%、飽和度都在 30% 以下，唯獨那圈藍是滿飽和——
它成了整屏唯一的「彩色事件」，於是看起來不像這套材質長出來的，像從別的應用截圖貼上去的。

所以真正要修的不是「藍不好看」，而是**一個低飽和的世界裡不該出現一塊滿飽和的色**。
按這個診斷，改版動了兩條軸，其餘規則（焦點靠打亮、強調只做線、柔光帶、圓角檔位）一條沒動：

| 維度 | 舊 | 新 | 為什麼 |
| --- | --- | --- | --- |
| 材質 | 灰藍 `#1F232B`（飽和 28%） | 石墨 `#1F2024`（飽和 13%） | 材質先退成中性，才裝得下任何一支強調色；偏藍的底會把非藍強調色全襯成外來戶 |
| 強調 | 品牌藍 `#5980FF`（飽和 100%） | 香檳金 `#DFB77C`（飽和 44%） | 暖金屬貼在中性石墨上是「鋼與黃銅」，冷暖對比自帶層次；飽和度砍掉一半，不再搶焦點 |
| 亮面 | 冷白 `#E7ECF5` | 暖白 `#F0EAE0` | 亮面和強調色是同一個光源，冷白配金環會互相打架 |
| 選中 | 18% 藍染色底 + 藍環 + 白字 | 抬升面 + 金環 + **金字** | 染色在藍上勉強成立，混到暖金就變成褐色泥 |

#### 怎麼選的：六支候選並排比

`tools/neumorphism-preview.py` 會額外輸出 `docs/preview/.local/palette.png`：同一塊石墨材質上並排畫六支強調色
（海報卡細環 / 選中膠囊 / 亮面焦點按鈕 / 當前頁圖示 / 選集當前集 / 進度條 / 名次星標 / 強調色文字），
第一列就是上一版的品牌藍，用來對照「為什麼換」。

- **品牌藍**：滿飽和，就是問題本身，淘汰；
- **香檳金 `#DFB77C`**：低飽和暖金屬，冷暖對比清楚，選中態和進度條都成立，**採用**；
- **暖銅 / 玫瑰銅 `#DE9E77`**：偏粉，少了金屬的「貴」，更像生活類應用；
- **琥珀 `#E8A33D`**：太飽和，和提示黃 `#FFC24B` 撞車，兩套暖色會在同一屏裡互相打散；
- **霧青 `#86C4B4`**：和石墨是一家人，但整體偏「醫用 / 科技」，缺少「影視」的溫度；
- **霧銀 `#C9D3E2`**：近乎無彩，選中態和常態分不開，等於放棄了強調色。

#### 對比度（WCAG）

| 組合 | 對比度 | 用在哪 |
| --- | --- | --- |
| 香檳金 `#DFB77C` / 底色 `#1F2024` | 7.6:1 | 細環、進度條、名次星標、強調色文字 |
| 香檳金 / 抬升面 `#2F323A` | 6.7:1 | 選中態的文字與細環 |
| 暖白亮面 `#F0EAE0` / 底色 | 13.4:1 | 焦點態、主操作 |
| 暖近黑 `#1A1612` / 暖白亮面 | 14.6:1 | 焦點態、主操作的字 |
| 深銅 `#A8793C` / 暖白亮面 | 3.2:1 | 亮面上的那圈細環（非文字，門檻 3:1） |

#### 下次再改色板

> 這一節寫於第二次改版，當時色值還寫死在 `TvStyle.kt` 裡、細環色還分兩檔。
> 第三次改版之後**色值住在 `TvTheme.kt`**（每個主題三個色值 + 文字基色 + 強調色 + 提示色），
> 細環已經不存在，流程改成下面這樣。

1. 改 `TvTheme.kt` 裡對應主題的色值與 `tools/theme-preview.py` 頂部的同一張表，
   兩處必須一一對應（`tools/verify-button-system.py` 第 15 條會核對每個色值）；
2. 跑 `python3 tools/theme-preview.py`，看 `docs/preview/theme.png`：先確認三檔材質分得開，
   再確認「常態 / 按進去 / 打亮」三個臺階在淺色底與深色底上都讀得出來；
3. 強調色只做線與小色塊，過一遍非文字 3:1 即可；文字基色對底色要過 WCAG AA（4.5:1）；
4. `tools/neumorphism-preview.py` 頂部的色板是**深邃暗調**那一套的映象，改了深色主題要同步；
5. `app/src/main/res/values/styles.xml` 的 `windowBackground` / `colorAccent` 跟著改
   （啟動第一幀的兜底配色）；**桌面圖示與電視桌面卡片不在執行時主題裡**，由
   `tools/app-icon.py` 生成——改色改腳本頂部的材質表，再跑 `python3 tools/app-icon.py
   --emit-vector` 重出矢量与位图，没有设备时的校对图是 `docs/preview/.local/icon.png`。

### 為什麼焦點不是「強調色實心塊」

第一版把焦點做成了 `#5980FF` 實心 + 近黑字。離線預覽三套並排一比就看出來了：一塊高飽和的藍
貼在灰藍材質上，像是從另一個應用截圖貼過來的——**焦點色和選中色都比頁面本身更"吵"**。

新擬態裡「被打亮」才是焦點的母語：同一塊材質被推到最亮的一檔（[lit]），
再補一層光暈。於是：

- 焦點面 `#F0EAE0` 對頁面底色 `#1F2024` 是 **13.4:1**，比任何強調色都亮；
- 暖近黑字在它上面是 **14.6:1**，3 米外讀起來毫無壓力；
- 強調色退到「線」上（進度條、名次星標），面積不到一屏的千分之一。

當時還給焦點補了一圈強調色細環（石墨上香檳金、亮面上深銅）。**那一圈環在第三次改版裡被刪掉了**
（見 [2.2](#22-主題改版2026-10-07十四套材質--去掉選框的顏色)）：焦點現在只靠「打亮 + 光暈」，
不再有任何顏色。

**選中態**：不再染色。品牌藍時代 18% 藍混進凸起面還能得到一塊「石板藍」，
換成暖金之後同樣的配方混出來是一塊褐色泥，比底色還悶。現在選中 = **抬一檔明度**
（`selectedFace` = `surfaceHigh`）。第三次改版又把「按進去」加成了另一種選中表達，
並且把細環與強調色文字一起去掉，見 [2.2](#22-主題改版2026-10-07十四套材質--去掉選框的顏色)。

**主操作**（詳情頁「開始觀看」）用同一個亮面板，但不帶光暈——一屏一個亮塊，
不用點也知道它是主操作；焦點移上去時它才多出一圈光暈。

### 2.2 主題改版（2026-10-07）：十四套材質 + 去掉選框的顏色

第二次改版之後仍然有一處沒解決：**焦點框與選中項還是一圈帶顏色的線**。
哪怕換成低飽和的香檳金，它依舊是整屏唯一一塊「有顏色的事件」，看起來不像這套材質長出來的。
本輪把兩件事一起做掉，規則收斂成一句話：

> **狀態只用「凹 / 凸 / 亮」三個臺階表達，選框不帶顏色；材質本身可選。**

| 狀態 | 畫法 | 用在哪 |
| --- | --- | --- |
| 常態 | 凸起面 `surface`（`RAISED`） | 按鈕、卡片、設定項 |
| 選中（按進去） | 凹陷面 `selectedWell` + `SoftStyle.INSET`（左上更深、右下更亮） | 開關、播放選項、設定項、**主題行** |
| 選中（抬一檔） | 抬升面 `selectedFace` + 更深的柔光（`depth` 1.3） | 頂部當前頁圖示 |
| 當前項（常亮） | 常亮的 `lit` 面板 + `onLit` 字 | 選集網格里的當前集（= 主操作那一檔：一屏裡那塊「本來就是它」的亮色） |
| 焦點 | 最亮的 `lit` 面板 + `litGlow` 光暈（`depth` 1.2–1.35） | 全站唯一的焦點表達 |
| 主操作 | 常亮的 `lit` 面板（不帶光暈） | 詳情頁「開始觀看」這類一屏一個的按鈕 |
| 禁用 | 壓平的凹槽 `well` + 40% 透明度 | 不可用按鈕 |

為什麼選中要分兩種：**周圍是什麼，決定「選中」往哪個方向走**。
一排凸起的按鈕裡，凹下去的那一個最好認；而選集網格里格子挨著格子，
再凹一層的明度差在 20 個格子裡讀不出來，所以那裡改用「抬一檔 + 更深的柔光」。兩條路徑都不帶顏色。

選集裡的**當前集**比「選中」更特殊：20 個格子裡
3% 的明度差讀不出來——「你在看第幾集」卻是這張網格唯一必須一眼看到的訊號。
因此它借用主操作那一檔（常亮的亮面板 + 亮面上的字），和舊版的「金環 + 金字」一樣醒目，
但不帶顏色；焦點落在它上面時只是多一圈光暈、放大 1.05。

| 11 | 灰霧玫瑰 Dusty Mauve | `#E4DEE1` | `#FAF7F9` | `#BCB2B8` | 高階、柔雅 |
| 12 | 蒼巖橄欖 Pale Olive | `#DFE1D8` | `#F8F9F1` | `#B9BDAE` | 建築、藝術 |
| 13 | 石墨 Graphite | `#34383D` | `#41464D` | `#25282C` | 專業、硬朗 |
| 14 | 午夜藍 Midnight Blue | `#30363F` | `#3D4550` | `#242930` | 科技、旗艦 |

前四套是本輪之前就在的（它們的氣質欄寫的是**適用場景**），後十套是 2026-10-07 追加的
（八套淺色 + 兩套深色，氣質欄按設計稿原樣）。淺色主題的**焦點面就是該主題的亮部陰影色**
（`#FBFCFA` 這類近白）——底色到純白只有 1.1–1.3:1 的餘地，不另造一檔「比高光更亮」的白。

其餘檔位全部**派生**，十四套共用同一套規則（`TvTheme` 裡的 `mix` / `alpha`）：

```
凸起面 surface      = 底色 → 亮部阴影色 45%
抬升面 surfaceHigh  = 底色 → 亮部阴影色 72%
凹陷面 well         = 底色 → 暗部阴影色 45%
深凹槽 wellDeep     = 底色 → 暗部阴影色 72%
投影 / 高光         = 表里两档阴影色，深色主题 62% 强度、浅色主题 72%
内阴影              = 暗部色（左上）/ 亮部色（右下）；浅色主题的配方更重（72% / 50%）
文字四级            = 文字基色的 100 / 84 / 70 / 62%
焦点面 lit          = 浅色主题纯白、深色主题暖白 #F0EAE0
```

文字四級從舊的 100 / 80 / 65 / 40 調高了一檔，原因是**底色換了**：40% 那一檔壓在
新底色上只剩 2.1:1（舊底色 `#1F2024` 更暗，同樣一檔還有 3.6:1）。現在最低一檔
在兩個方向上都過 3:1——十二套淺色 3.10–3.46、兩套深色 5.19–5.33；正文 7.8–9.6（淺）/ 10.6–11.1（深）
（由 `tools/theme-preview.py` 的自檢逐套列印，低於門檻直接報錯退出）。

為什麼不照抄教科書式新擬態的「元素與底色完全同色」：電視 3 米外看，
3% 的明度差是分不出「哪裡是按鈕」的（這是第一次改版就踩過的坑）。
因此凸起面 / 凹陷面各挪一檔，**但只挪一檔**——層次主要還是柔光在說，
這一點與教科書一致。

文字基色是「淺色主題用深墨、深色主題用暖白」，所以 `TvStyle.text` / `muted` 這類令牌
在兩個方向上都能直接用。**唯一不跟主題的是播放介面**：它壓在影片上，永遠用
`playerText` 的暖白（淺色主題下如果跟著變成深色字，標題條與控制層會完全看不見）。

#### 主題怎麼存、怎麼切

- **存**：`native-theme-v1` 一個只有一項的獨立 SharedPreferences（`TvThemeStore`），
  按 `storedValue`（`soft-gray` / `creamy-milk` / `deep-dark` / `cool-mint` /
  `porcelain` / `moonstone` / `ivory-sand` / `silver-sage` / `blue-haze` / `champagne-silk` /
  `dusty-mauve` / `pale-olive` / `graphite` / `midnight-blue`）落盤。
  它**不進** `com.hgtv.star.core` 的 `Library`：那裡裝的是內容與觀看記錄，
  還要參與手機備份的合併與衝突處理，讓一套配色跟著備份在裝置之間搬家沒有意義。
- **讀**：`MainActivity.onCreate` 裡在建任何檢視之前同步讀一次（一個很小的檔案），
  順手把視窗底色也換成該主題的底色，啟動那一幀不會閃出另一套材質。
- **切**：設定頁底部是**整寬的「主題外觀」分組**，裡面 `chunked(4)` 排成一行 4 個的主題晶片
  （14 套 = 4 行，最後一行用空位佔住列寬，晶片不會被拉成半屏寬）。晶片就是全站統一的
  緊湊檔按鈕，標籤是「中文 英文」，選中態是**按進去**的凹槽——凹下去的那一枚就是當前主題，
  下面還有一行「當前：瓷白 Porcelain · 極簡、奢華」。點一下 → 落盤 → `TvStyle.applyTheme()` →
  `Soft.trim()`（柔光點陣圖裡烤著上一套材質的投影色）→ `showCatalog()` 重建當前頁面 →
  焦點回到剛點的晶片。柔光快取的 key 裡也帶上了主題，雙保險。
  **為什麼不是一行一個主題**：14 × 60dp 會把設定頁頂出螢幕，晶片網格只佔 4 行。
- **反悔**：十四套材質都只改色值，幾何、圓角、柔光帶、按鈕檔位、焦點餘量一件不動，
  所以換主題不可能改變佈局——這也是 `tools/verify-button-system.py` 會核對的一條。

#### 順手修掉的兩處「系統控制元件的顏色」

「選框不帶顏色」這條規則同樣適用於彈窗裡的開關：備份恢復的「同時恢復播放設定和內容分類」
與版本更新裡的「自動檢查並下載更新」原來都是系統 `CheckBox`，勾選色是系統自帶的一套
（還會在淺色主題裡跳出一個灰框）。現在兩處都換成全站統一的開關按鈕（選中 = 按進去），
`CheckBox` 在整個工程裡已經清零，靜態校驗會攔住回退。

#### 怎麼複核

`python3 tools/theme-preview.py` 會輸出 `docs/preview/theme.png`：十四套材質排成 7 列 × 2 行，
每列畫出三檔材質色塊、三個狀態臺階（常態 / 按進去 / 打亮）、海報卡的常態與焦點、
強調色只做線的三個例子、以及四級文字。它用的是與 `TvTheme.kt` 相同的派生公式，
`tools/verify-button-system.py` 會核對兩邊的色值表——改色時先重跑這張圖，
比在真機上逐個改值快得多。`tools/neumorphism-preview.py`（整頁排版預覽）仍然是
深邃暗調那一套的令牌映象。

## 3. 柔光怎麼畫（`TvSoft.kt`）

`SoftDrawable` 有四種形態，任何控制元件的外觀都必須從這四種裡挑一種：

| 形態 | 畫法 | 用在哪 |
| --- | --- | --- |
| `SoftStyle.RAISED` | 預渲染柔光點陣圖（右下深投影 + 左上高光 + 可選外發光）+ 面板填充 | 按鈕、卡片、圖示入口、彈窗、播放器底座 |
| `SoftStyle.INSET` | 面板填充 + 裁剪到面板內畫兩條方向相反的內陰影漸變 | 搜尋框 |
| `SoftStyle.RING` | 只有一圈描邊，無投影無底 | 目前沒有呼叫方：留給「底板不能改色、只能補一圈」的場合。**它不允許再畫強調色**——2026-10-07 之後全站的焦點都不帶顏色，真要補圈只能補 45% 文字基色的中性細線（`TvStyle.focusLine`） |
| `SoftStyle.SHADE` | 面板 + 徑向暗角 | 壓在封面上的「海報井」 |

幾何約定：**底板 = 控制元件 bounds 四邊各內縮 `band`**。因此控制元件的 `padding` 必須 ≥ `band`，
否則內容會壓到柔光帶裡。全站控制元件的高度令牌（`BUTTON_NORMAL` 等）指的是**底板高度**，
控制元件實際高度 = 令牌 + `2 × SOFT_BAND`。

效能：點陣圖按「尺寸 + 圓角 + 形態 + 深度 + **主題**」做 LRU（24 條），一屏裡同尺寸的卡片共用一張；
半解析度渲染再放大，投影本來就是模糊的，看不出差別。
低記憶體裝置在 `onCreate` 裡把 `Soft.quality` 調小（見 `MainActivity.onCreate`）。
點陣圖裡烤著當時的投影 / 高光色，所以 key 裡必須帶主題（`TvStyle.themeId`），
`TvStyle.applyTheme()` 還會整體 `Soft.trim()` 一次。

## 4. 元件清單（`TvComponents.kt`）

- `TvButton`：**全站唯一的按鈕實現**。尺寸走 `ButtonSize`（40 / 48 / 56dp 底板）、
  外觀走 `ButtonTone`（主操作 / 常規 / 文字）。狀態：
  常態 = 凸起面板 + 正文色；選中 = **按進去**（凹陷槽 + 內陰影）+ 正文色；
  **焦點 = 亮面板 + 光暈 + 近黑字**；主操作 = 常亮的亮面板（不帶光暈）；
  禁用 = 壓平的凹槽 + 40% 透明度。焦點與選中都不帶顏色。
- `IconButton`：頂部導航的圓形入口，常態凸起圓盤 + 正文色圖示、
  當前頁**抬一檔**（更深的柔光，圖示仍與常態同色）、焦點亮圓盤 + 光暈 + 近黑圖示。
  控制元件最小邊長 = `BUTTON_NORMAL + 2 × SOFT_BAND`，呼叫方給 `lp(-2, -2)` 即可。
- `ToggleChip`：短劇 / 漫劇互斥開關，就是 `TvButton` 的選中態。
- `PosterCard`：一塊凸起底板，裡面嵌海報井（`SHADE` 暗角）、角標、進度條與兩行文字。
  卡片的焦點態和按鈕不同——卡里是圖片，底板換不成亮面，因此焦點 = 抬一檔 + 更深的柔光
  + 光暈 + 劇名轉全白。
- `SectionHeading`：粗體標題，從內容線開始；2026-10-12 起不再有強調色圓點與「更多 ›」。
  2026-10-12 起不再有右側「更多 ›」：劇架行末的「檢視全部」底板就是入口。
- `EpisodeCell`：選集方格，常態凸起、**當前集是常亮的亮面板**
  （3% 的明度差在 20 個格子裡讀不出來，所以借主操作那一檔）、焦點是亮面板 + 光暈。
- `SeekIndicator`：進度條，**保持原樣**（4dp 軌道 18% 白 + 白色已播 + 10dp 白色圓滑塊）。
  它只出現在播放介面，跟著那條「播放介面不套新擬態」的規則走，
  顏色取 `playerLine` / `playerText`，不跟主題。
- `TvDialog`（`TvDialog.kt`）：**全站唯一的模態框**，一塊 24dp 圓角的大號凸起面板，
  柔光帶 9dp、投影更深一檔，背景壓暗 66%。列表項的「當前選擇」也是按進去的凹槽。
- `EpisodeGrid`（`EpisodeGrid.kt`）：簡介頁與播放介面共用的選集網格。
  只有播放介面有背板（浮層漸變，壓在畫面上）；簡介頁**不套背板**，網格直接落在頁面上，
  左右與頁面內容線對齊。兩處的文字色不同：播放介面固定 `playerText` 暖白，簡介頁跟主題。
- `PlaybackMenu`（`PlaybackMenu.kt`）：播放器設定面板，底座是原來的三段黑漸變（播放介面不套新擬態），
  裡面的選項按鈕仍然是全站統一的膠囊按鈕（選中 = 按進去）。

## 4.1 離線預覽

沒有裝置時用 `tools/neumorphism-preview.py` 校對觀感：它用 PIL + numpy 復刻
[SoftDrawable] 的繪製順序（柔光 = 形狀的模糊剪影 + 偏移、凹陷 = 兩條 45° 漸變裁剪到面板內、
暗角 = 徑向漸變），令牌數值與 `TvStyle.kt` 一一對應，輸出 `docs/preview/.local/home.png`、`docs/preview/.local/sheet.png` 與 `docs/preview/.local/palette.png`（六支強調色候選並排，第一列是上一版的品牌藍）。

```sh
python3 tools/neumorphism-preview.py          # 整页排版（深邃暗调那一套令牌），需要 Pillow + numpy
python3 tools/theme-preview.py                # 十四套主题 × 状态台阶，输出 docs/preview/theme.png
```

這幾個數值都是它比出來的（前兩條是第一次改版、第三條是第二次改版，第四次改版把「細環 / 金字」
換成了「按進去」，見 [2.2](#22-主題改版2026-10-07十四套材質--去掉選框的顏色)）：

- `shadowDark` 從 35% 提到 **42%**。35% 時凸起面與底色（明度只差 3%）在整屏縮圖裡糊成一片，
  55% 以上投影又會變成一道硬邊；
- 焦點從「實心強調色」換成 **亮面板 + 強調色細環**（三套配色並排比過，見
  「為什麼焦點不是強調色實心塊」）；
- 選中態從「18% 染色底」換成 **抬一檔明度 + 金環 + 金字**：同一套配方在藍上成立、在暖金上變成褐色泥
  （見 [第 2.1 節](#21-色板改版2026-10-07石墨--香檳金)）；
- 強調色從品牌藍換成香檳金：`docs/preview/.local/palette.png` 六列並排比出來的，比在真機上逐個改值快得多。

`tools/theme-preview.py` 是主題改版新增的那張：十四套材質排成 7 列 × 2 行，每格畫出三檔材質、
三個狀態臺階（常態 / 按進去 / 打亮）、海報卡的常態與焦點、強調色只做線的三個例子、四級文字。
它的色值表與 `TvTheme.kt` 一一對應，`tools/verify-button-system.py` 第 15 條會核對，
派生公式（45% / 72% / 62% / 72% / 文字四級）也與 `TvTheme` 的 `mix` / `alpha` 相同。
它同時是**十四套主題的迴歸門檻**：腳本按 WCAG 公式算正文、四級文字、亮面上的字、
焦點面 / 凹陷面 / 抬升面與底色的對比度，任何一項低於門檻就直接報錯退出，
並把每一套的實測值打在終端上（加主題或改色板之後先看這張表，再去看圖）。

預覽**不是** Android 渲染器的替代品：字型、字距、真實海報、遙控器焦點移動、
低端 GPU 上的幀率都不在這裡驗證。

## 5. 必須保持的不變數

改版只動外觀，以下結構一件都不能改，`tools/verify-button-system.py` 會靜態核對：

1. **按鈕只有一套實現**。除 `TvComponents.kt` 外不允許出現第二個繼承 `TextView` 的控制元件，
   也不允許別處呼叫 `paintButton(`。
2. **模態框只有一套實現**。系統 `AlertDialog` 只允許出現在 `TvDialog.kt`。
3. **滾動容器的裁剪規則不變**：容器自己 `clipChildren = false` + 外殼 `tvScrollHost` `clipChildren = true`；
   每個縱向滾動容器必須 `focusBleed()`（或註明 `focus-bleed-exempt`）並掛在 `tvScrollHost(` 上。
   柔光帶是控制元件自己的事，與這條規則互不替代。
4. **焦點餘量不變**：`FOCUS_BLEED = 7` / `FOCUS_BLEED_VERTICAL = 12`，`FOCUS_SCALE = 1.05`。
5. **按鈕高度只引用令牌**：`minimumHeight` 只能寫成 `dp(size.height + 2 * TvStyle.SOFT_BAND)`
   或 `dp(TvStyle.BUTTON_XXX + 2 * TvStyle.SOFT_BAND)`。
6. **內邊距不再各寫各的**：橫向內邊距只能來自 `size.pad`（`paintButton` 內部），
   呼叫方不再自己拼 `setPadding(dp(32), ...)` 這類字面量。
7. **長期持有的控制元件重新掛載必須走 `rehost()`**。判定不看具體控制元件名，看形狀：縮排 4 空格宣告的屬性（跨函式存活）出現在帶 `removeAllViews()` 的重建函式里、被裸 `addView` 掛載、且該函式沒有重新給它賦值 —— 這就是「第二次重建拋 `IllegalStateException`」的形狀，`tools/verify-button-system.py` 第 10 條按此核對。
8. **焦點圖（`nextFocusXxxId`）與按鍵處理一行不改**：換皮不動互動。
9. **選框不帶顏色**：`ring=` 上不允許出現 `TvStyle.accent`，`accentGlow` 已經刪除，
   選中態只能是「按進去」（`TvStyle.well` + `INSET`）或「抬一檔」（`TvStyle.selectedFace`），
   焦點態只能是「打亮的 `lit` + `litGlow`」。強調色只允許出現在進度條、名次星標。
10. **主題只改色值**：`TvStyle` 的顏色令牌全部來自 `TvTheme`，幾何 / 圓角 / 柔光帶 /
    按鈕檔位 / 焦點餘量一個都不能跟主題變。換主題必須 `Soft.trim()`，柔光快取的 key 必須帶主題。
11. **主題不進內容庫**：只存在 `native-theme-v1`（`TvThemeStore`），
    不參與 `Library` 的備份合併；`TvTheme` 的四個 `storedValue` 是落盤契約，不能隨手改。
12. **播放介面的字與線不跟主題**：壓在影片上的文字一律取 `playerText` / `playerDim`，
    進度條軌道取 `playerLine`，否則淺色主題下會變成深色字、完全看不見。
13. **工程裡不允許再有系統 `CheckBox`**：開關一律用全站統一的按鈕（選中 = 按進去），
    系統控制元件的勾選色是自帶的一套，與「選框不帶顏色」衝突。

## 7. 驗證邊界

靜態檢查（`tools/verify-button-system.py`、`gradlew :core:test :app:lintDebug :app:assembleDebug`）
只能證明「只有一套實現、能編譯、lint 無錯、選框裡沒有顏色」。
`tools/theme-preview.py` 能證明十四套材質的**派生結果**與狀態臺階在離線渲染下成立，
但**新擬態的觀感、投影在低端 GPU 上的幀率、遙控器焦點在 4K 畫布上的對比度必須在實體電視上驗收**，
本輪沒有實體裝置（本機只有 JDK 17 + Android SDK，模擬器系統映象是空殼、下載失敗），
因此這些仍是待驗收項：

- 十四套主題在電視上的實際觀感，特別是**十二套淺色主題**在 3 米外的
  焦點辨識度。這一條是**已知的固有限制**，不是沒測出來：淺色主題的底色到純白只有
  `1.12:1`（優雅奶白）～`1.28:1`（高階柔冷），兩套深色主題同一項是 `10.3–10.9:1`。
  淺色底上「打亮」的餘地只有到白為止，因此焦點實際上由三個弱訊號疊加承擔：
  面變白 + 一圈光暈 + 放大 1.05。`tools/theme-preview.py` 把這一項的門檻定在 1.10，
  正是承認這個上限；**如果真機驗收不合格，唯一不引入顏色的加強手段是給焦點面補一圈
  45% 文字基色的中性細線（`TvStyle.focusLine`）**，那仍然不是「帶顏色的選框」，
  但會回到「描邊」的觀感，因此留作最後手段而不是預設；
- 換主題後整頁重建的那一瞬間（`showCatalog()`）在低端機上的耗時與閃動；
- 播放介面在淺色主題下的可讀性（本輪把它的字與線固定成暖白，但只有真機能確認
  標題條與控制層的對比度夠用）；
- 主題外觀分組的 4 行晶片（一行 4 個）+ 上面兩列設定項在 720p 畫布上的換行與焦點串聯
  （原始碼裡按行號對齊，越界時停在原地）；14 套材質排下來設定頁會比一屏高一點，需要滾動。
