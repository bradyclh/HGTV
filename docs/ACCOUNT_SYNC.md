# 紅果帳號同步接入調查（2026-09-22）

使用者目標：用本人抖音帳號登入紅果，在電視端同步紅果收藏、觀看歷史及續播位置。保持使用者只安裝 APK、無需自行部署服務。

## 當前結論

本輪沒有實現紅果登入或雲端同步。缺少經過驗證的紅果使用者授權、帳號對應、收藏和進度讀寫介面；普通抖音 OAuth 授權不能作為這些權限已獲授予的證據。不得將頭像或暱稱獲取成功標記為“紅果已登入/已同步”。

- 當前客戶端 `ContentRepository` 使用遊客內容請求，搜尋參數 `user_is_login=0`；`Library` 的收藏和進度在本機 SharedPreferences，沒有平臺帳戶會話。
  App 搜尋介面對匿名裝置返回空回應（搜尋預設退回官網搜尋），原生版因此提供了一個**可選**的「搜尋登入態」本機設定：
  用手機掃碼貼上 App 抓到的 `x-tt-token`，只存在本機、只用於搜尋請求、不進備份檔案。
  它是**介面層的口令**，不是紅果帳號登入：沒有帳號身份、沒有收藏與進度的雲端同步。
- 檢查紅果官網首頁、首頁直接引用的三個業務腳本，未找到登入入口或帳戶同步實現。範圍僅限這些公開資源，不能據此推斷平臺沒有內部或合作介面。
- [抖音 SDK 概述](https://open.douyin.com/platform/resource/docs/develop/summarize/sdk) 描述抖音授權和獲取公開使用者資料；更多資料能力需對應申請。未找到明確開放紅果收藏和觀看進度的 scope。
- [抖音網站 OAuth 文件](https://open.douyin.com/platform/resource/docs/develop/permission/web/oauth2) 要求註冊開發者配置 ClientKey / ClientSecret，透過授權碼交換令牌，並提示應用金鑰放在客戶端不安全。專案當前未配置該應用的平臺註冊憑據，不能挪用紅果官方 App 的身份和應用金鑰來聲稱已授權。
- 本輪沒有收集使用者密碼、驗證碼、Cookie 或令牌，沒有登入或改動使用者的平臺收藏和進度。

## 接通所需證據

1. 平臺允許此應用使用的授權方式、ClientKey、應用包名/簽名配置，以及是否必須有服務端保管應用金鑰。只有可安全執行於客戶端的授權流才能直接保持純 APK；服務端必需時必須另行明確託管方案，不能將金鑰塞入 APK。
2. 抖音身份到紅果帳戶的受支援對應及使用者資料授權範圍。
3. 收藏分頁、歷史與精確播放進度讀取介面，含欄位定義、權限錯誤及會話過期行為。
4. 先完成本人真實帳號只讀驗證，再接入收藏和進度寫回。雙端衝突按更新時間與明確的播放會話處理；不能簡單取最大集數，避免覆蓋使用者重新觀看較早集的意圖。
5. 退出、過期、換號測試；按平臺帳號隔離快取，保留並區分既有本地遊客記錄，避免串號。

帳號功能依賴上述平臺接入條件，不是只增加一個 UI 登入按鈕即可交付。新版本中的“手機輸入”二維碼僅傳送區域網搜尋詞；設定裡的“版本資訊”只讀出本機版本號，都不是紅果帳號登入。
