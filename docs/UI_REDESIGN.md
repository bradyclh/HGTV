# 介面改版：極光 TV 式排版與設計令牌

> **本檔案的色板與形狀語言已被新擬態改版取代**，見 [新擬態介面改版說明](UI_NEUMORPHISM.md)。
> 仍然有效的是這裡的**排版結構**（頂部頻道導航、分割槽橫向劇架、海報卡、選集網格）、
> **焦點與裁剪規則**、**按鈕規範**與**頁頭隨滾動收起**——本輪只換了材質，
> 下面提到的 `#1B1B20` / `#1E1E21` / 6dp 圓角 / 「焦點統一白底 + 深字」都請以新檔案為準。

本輪把原生版的介面按「騰訊影片極光 TV」的排版邏輯重做了一遍：近黑沉浸底色、頂部頻道導航、
分割槽橫向劇架、圓角海報與統一的焦點反饋。改動集中在 UI 層，內容協議、簽名、播放與解密程式碼未動。

## 參考的排版結構

| 位置 | 極光 TV 的做法 | 本專案的實現 |
| --- | --- | --- |
| 頂部 | 左側品牌，右側輔助入口 | 品牌按鈕（回首頁）+ 右側 48dp 圓形圖示入口：搜尋 / 排行榜 / 設定 |
| 內容區 | 分割槽標題 + 橫向海報架，逐行向下滾動 | `HomeScreen`：`SectionHeading` + `HorizontalScrollView`，行內橫向記憶位置 |
| 首頁首行 | 大卡推薦位 | `PosterCard` 的豎版海報架：一屏 6 張、行內 14dp 間距，劇名與狀態放在卡下 |
| 海報卡 | 圓角豎版海報，焦點放大並描邊 | `PosterCard`：7:10 圓角封面 + 左上角標 + 卡下劇名/狀態 + 底部進度 |
| 詳情頁 | 海報 + 資訊 + 膠囊主按鈕 + 集數網格 | `showDetail()`：完整豎版海報（左）+ 標題 / 簡介 / 膠囊主次操作（右）+ `EpisodeGrid` 集數網格 |
| 選集 | 底部抽屜，一頁 20 集 | `EpisodeGrid`：簡介頁與播放介面共用同一份網格，10 列 × 2 行圓角單元格 |
| 播放器 | 上鍵彈設定、下鍵彈選集 | `PlaybackMenu`：右側豎向面板，清晰度 / 倍速 / 畫面模式 / 定時 四項，選項等分並自動換行 |

**沒有做全屏大圖輪播**：介面只提供約 7:10 的豎版封面，拉伸成 16:9 會明顯變形；
按 `CENTER_CROP` 鋪滿又只剩中間一條，且要多快取一張全屏點陣圖。低配電視的記憶體預算不支援這個取捨，
因此推薦位改用「3 列橫卡 + 浮層」表達同一層級。

同一條理由也決定了詳情頁的排版：早期版本把封面 `CENTER_CROP` 成整幅通欄劇照、標題壓在圖上，
結果封面只剩中間一條，文字還要靠一層半透明漸變撐可讀性。現在改為**海報完整顯示 + 資訊右置**：
海報按介面原始比例（約 7:10）`FIT_CENTER` 整張放進圓角卡座，高度取屏高的 48%（上限 430dp），
標題、集數題材、簡介與主次按鈕排在右側的純色頁面上，因此不需要壓暗層、模糊層或文字投影。

## 焦點與裁剪

焦點縮放會被父容器裁掉，這是電視端最容易踩的坑。規則如下，改動佈局時必須保持：

1. **行 / 列容器一律 `clipChildren = false`**（`TvComponents.tvRow()/tvColumn()` 與
   `MainActivity.row()/column()` 已經預設帶上）。中間任何一層行 / 列一旦裁剪，
   貼在它邊緣的那張卡片 / 那個按鈕的焦點反饋就會被切平。
2. **裁剪邊界取的是「直接父級」的 `clipChildren`，不是控制元件自己的**。框架裡寫死了：

   ```java
   // View.setDisplayListProperties()
   renderNode.setClipToBounds(mParent instanceof ViewGroup
           && ((ViewGroup) mParent).getClipChildren());
   // 软件绘制路径同样只看 parentFlags & FLAG_CLIP_CHILDREN
   ```

   於是同一條需求必須拆成兩處來做，缺一不可：

   - **滾動容器自己 `clipChildren = false`**（`ScrollView.focusBleed()`）。這個開關管的是
     「子控制元件會不會被裁到子控制元件自己的邊界上」；開啟它等於把列表裁在列表自己的邊界上——
     列表本來就有整份內容那麼高，裁了等於沒裁，卻正好把第一行 / 最左邊那張卡放大後
     畫到列表邊界之外的那條描邊切掉，觀感就是「最左邊的選中框只剩一半、上邊框看不見」。
   - **滾動容器的直接父級 `clipChildren = true`**（`TvComponents.tvScrollHost()`）。
     把滾動內容關在可視區裡的那道裁剪只能由父級提供；父級不裁，上滾的卡片就會畫到
     滾動容器之外，蓋住頁頭那一排按鈕（頁頭是透明底，觀感就是「按鈕跑到列表後面，很亂」）。
     外殼裡只放滾動容器一個子控制元件，因此開啟裁剪不會碰到任何按鈕的焦點放大。

   餘量仍然做在容器**內部**：`focusBleed()` 四邊都留內邊距——左右 `FOCUS_BLEED`（7dp），
   上下 `FOCUS_BLEED_VERTICAL`（12dp，海報卡是豎的，向上溢位更多）。
   1.05 倍放大讓控制元件畫出自身 2.5%：175dp 寬的海報卡橫向 4.4dp，
   288dp 高的豎版卡縱向 7.2dp，4K 畫布上約 11.3dp。
   `clipToPadding = false` 保證不額外裁到內邊距框，這 7dp / 12dp 才真的可用。
   頁面容器因此比內容線早 7dp 開始（`pageBleed()`），滾動容器再補回來，內容仍然精確落在
   78dp 柵格上；工具欄、頁頭、搜尋行等非滾動內容各自補回這 7dp，保持同一條內容線。
3. 邊界本來就是整屏寬的滾動容器（簡介頁整頁滾動、播放器 HUD）不需要餘量，
   在原始碼裡用 `focus-bleed-exempt` 註明，`tools/verify-button-system.py` 會按這個標記核對；
   高度是 `WRAP_CONTENT`、內容永遠不超過自己的滾動容器同樣不需要外殼。
4. 圓角用 `clipToOutline` + `ViewOutlineProvider` 裁剪，而不是疊加遮罩點陣圖：
   不額外分配記憶體，縮放後邊緣依然銳利。

> 反面教材：改版前 `HomeScreen` 的劇架把第一張卡片放在滾動容器左邊界上，
> 放大後左側描邊落在邊界外 2.4dp，於是**整條左邊框消失**（右側因為內容更寬、可以滾動，反而看得見）。
> 詳情頁的「繼續觀看」按鈕左側同樣被 `actions` 行裁成平直切口，可以在
> `captures/episode-grid/detail-page-new-layout.png` 裡量出來。
>
> 另一條反面教材（2026-10-06 修）：為了補上面這條，曾經把滾動容器的 `clipChildren` 關掉，
> 結果列表不再裁剪——向上滾動時卡片畫到了頁頭那一排按鈕上面，頁頭是透明底，
> 觀感就是「紅果TV / 漫劇 短劇 / 搜尋 排行榜 設定 跑到列表後面，很亂」。
> 隨後改成「容器自己開啟裁剪」，描邊又被切回來了：**控制元件自己的 `clipChildren` 根本管不到
> 自己的裁剪**，它管的是子控制元件的裁剪。真正的分界線是「容器留餘量、外殼做裁剪」（第 2 條），
> 兩件事不能互相替代，`tools/verify-button-system.py` 第 9 條按這個規則核對。

## 元件清單（`TvComponents.kt`）

- `TvButton`：**全站唯一的按鈕實現**，尺寸走 `ButtonSize`（40 / 48 / 56dp 三檔）、
  外觀走 `ButtonTone`（主操作 / 常規 / 文字），焦點反饋與間距由元件自己負責。
- `IconButton`：頂部導航的圓形圖示入口（重新整理 / 搜尋 / 排行榜 / 設定），48dp 圓、24dp 圖示，
  當前頁用強調色填充；重新整理排在「搜尋」左邊，重新整理物件是當前這一頁。
- `ToggleChip`：短劇 / 漫劇互斥開關，就是 `TvButton` 的選中態。
- `PosterCard`：首頁架子與列表頁共用的豎版海報卡（`bind()` 負責角標、狀態與進度）。
- `SectionHeading`：粗體標題（可帶灰字副標題），從內容線開始。
  2026-10-12 起標題前不再有強調色圓點，也不掛「更多 ›」。
  2026-10-12 起標題行不再掛「更多 ›」：劇架行末的「檢視全部」底板就是入口。
- `EpisodeCell`：選集網格單元——網格方塊保留 6dp 圓角，但高度、字號、焦點反饋與按鈕同源。
- `TvDialog`（`TvDialog.kt`）：**全站唯一的模態框**，標題 + 內容 + 一排 `TvButton`，
  列表型彈窗每項都是整行左對齊的常規按鈕；應用裡不再有系統 `AlertDialog` 的 Material 文字按鈕。
- `EpisodeGrid`（`EpisodeGrid.kt`）：簡介頁與播放介面共用的選集網格——標題行、集數行、
  10 列 × 2 行 48dp 單元格、8dp 間距、漸變背板與四向翻頁只有一份實現，宿主只決定高度。

## 按鈕規範（2026-10-06 統一）

改版後按鈕的觀感問題集中在三件事：同一個介面裡按鈕高度不一（38 / 42 / 44 / 48dp 混用）、
內邊距與字號各寫各的（32/9、32/14、22/8、20/14 四種）、間距靠呼叫方手寫 `rightMargin`，
於是行尾多出 8dp、兩個按鈕貼在一起這類問題反覆出現。現在收斂成一套規則：

| 維度 | 規則 |
| --- | --- |
| 高度 | 只有三檔：緊湊 40dp（選單選項、行內文字入口）、常規 48dp（返回 / 分頁 / 重試 / 收藏 / 設定項）、主操作 56dp（詳情頁唯一強調按鈕） |
| 橫向內邊距 | 跟著檔位走：18 / 28 / 36dp，不再由呼叫方給 |
| 字號 | 15 / 16 / 17sp 粗體，與檔位繫結 |
| 圓角 | 一律膠囊 24dp（`RADIUS_PILL`）；選集網格方塊與海報卡片保留 6dp |
| 外觀 | 只有三種語義：`PRIMARY` 強調色填充、`SECONDARY` 12% 白填充 + 18% 白描邊、`GHOST` 無底文字；選中態統一強調色填充 |
| 焦點 | 統一白底 + 深字 + 放大 1.05，不再有 1.04 / 1.06 / 1.08 的差別 |
| 禁用 | 統一 40% 透明度 + 30% 白字 |
| 間距 | `GAP_INLINE` 12dp（同一行按鈕）、`GAP_TIGHT` 8dp（網格）、`GAP_BLOCK` 16dp（區塊）、`GAP_GROUP` 24dp（大分組）；由 `addButton` / `gapInto` 統一施加 |
| 最小寬度 | 92dp（文字按鈕除外），「收藏」這類短文案不會瘦成一條 |

落地位置：`TvStyle.kt` 存令牌，`TvComponents.kt` 存唯一的 `TvButton` 與繪製函式 `paintButton()`，
`TvDialog.kt` 存唯一的模態框，其餘檔案只呼叫。播放器底部的狀態行（清晰度 / 倍速 / 畫面模式 / 定時）
仍是純文字入口——它在畫面上方、不搶焦點，保留 20sp 的播放器排版，不進按鈕族。

防止回退：`tools/verify-button-system.py` 靜態校驗上述規則（唯一實現、三檔高度、令牌化內邊距、
焦點縮放唯一、彈窗統一、膠囊底色只用令牌），改動繞過 `TvButton` 會直接失敗。
它是原始碼級護欄，不替代真機驗收。

## 選集

簡介頁的選集不再自己寫一套網格，也不再是「上一組 / 下一組 / 跳轉集數」按鈕行：
頁面末尾直接貼一塊 `EpisodeGrid`，與播放介面按「下鍵」彈出的面板長得完全一樣——
同樣一行「選集 + 正在看第 X 集 · 共 N 集」、同樣一行「第 X—Y 集」、同樣 10 列 2 行單元格。

- 播放介面：`EpisodePanel` 只是把同一個網格放進貼底、整寬、約 300dp 高的透明彈窗。
- 簡介頁：網格整幅貼在頁面末尾。兩處宿主不同，翻頁方式完全相同。
- 一頁 20 集，四向都是「到邊緣再翻頁」：左右到本行兩端翻相鄰頁，第一行按上翻回上一頁，
  最後一行（或本頁只有一行時）按下翻到下一頁；只有確認單元格才換集，翻頁只移動焦點。
- **沒有目標頁時按鍵交回焦點系統**（`EpisodeGrid.turn()` 越界返回 `false`）：
  播放面板裡沒有上一頁 / 下一頁時焦點停在原地；簡介頁第一頁第一行按上就離開選集，
  回到「繼續觀看 / 收藏 / 完整簡介」這一行——詳情頁不留頁頭，這是它唯一的向上出口，
  所以這條返回 `false` 的越界判斷不能改成「吃掉按鍵」，否則選集在簡介頁會變成焦點孤島。
- 兩處都不再有「跳轉集數」鍵盤，選中集數的路徑統一為「翻頁 → 確認」。

`MainActivity.button()` / `addButton()` 只是 `TvButton` 的薄封裝：按鈕高度、內邊距、圓角、
焦點反饋都來自元件，頁面只負責文案、語義與點選。間距也只有一個來源——橫向容器加左邊距、
縱向容器加上邊距，第一個子控制元件不留邊距，因此不會出現「兩個按鈕貼在一起」或「行尾多出 8dp 把整行推偏」。

## 返回鍵

- 播放介面：先收浮層（設定選單 / 控制條），再回簡介頁。
- 簡介頁：回列表。
- 集合頁：回首頁並恢復原焦點。
- 首頁：焦點不在頂部導航時，先回到導航；**導航上再按返回彈出確認框**（`confirmExit()`），
  確認才 `finish()`，取消則焦點留在導航上。彈窗走全站統一的 `TvDialog`，
  焦點預設落在「取消」，誤按返回不會退出應用。

## 播放器選單

播放介面去掉了舊的一行文字操作（播放 / 上一集 / 下一集 / 選集 / 播放設定），改成兩個方向鍵各管一件事：

- **上鍵**（或選單鍵）開啟 `PlaybackMenu`：右側豎向面板，自上而下是「清晰度 / 倍速 / 畫面模式 / 定時」，
  每項的選項等分排在專案名右側，定時 8 個選項按每行 4 個換行。
- 上下換專案（含換行），左右換選項，確認立即生效，返回收起整個浮層；四向都鎖在選單內部，
  停在最後一行（定時）再按下鍵焦點留在原地，**不會跳進選集**——選單是「上鍵」開啟的浮層，
  在它裡面按到邊緣只表示到頭了，換介面仍然只由選單關閉後的下鍵 / 底部下拉箭頭負責。
- **下鍵**仍是 `EpisodePanel`，底部居中的下拉箭頭保留，作為觸控 / 滑鼠入口。
- 播放與暫停回到畫面中央的確認鍵和底部播放鍵圖示；上一集 / 下一集保留在媒體按鍵與選集中。
- 底部狀態行（清晰度 / 倍速 / 畫面模式 / 定時）只顯示當前值，點選可直接開啟選單的對應專案。

選單只做原生 View，沒有新增點陣圖；選項選中態用品牌色填充，焦點態沿用白底深字，與全站按鈕同一種手感。

## 首頁劇架與遠端長列表

- 頂部導航只有品牌、搜尋、排行榜、設定四個入口（`nav` 4 項：`switchTab(0..3)`，設定從原來的第 5 位挪到第 3 位）。
  收藏和觀看記錄不再佔導航位，改為首頁劇架；原來的兩個頁面裡「檢查更新」「管理記錄」按鈕分別跟著
  收藏集合頁、觀看記錄集合頁的頁頭。
- 首頁劇架按「歷史記錄 → 我的收藏 → 熱門推薦 → 熱門發現」排列，使用者加過稍後看內容時稍後看作為
  最後一欄出現。每欄最多十部（`take(10)`），超過十部才在行末掛「檢視全部」。來自本機記錄的
  歷史記錄、我的收藏、稍後看沒有資料時 `HomeScreen.render()` 直接不渲染這一行，因此不會留空位。
  歷史記錄按最近觀看排序，未看完的條目確認後直接續播，整劇看完的條目只顯示狀態；
  我的收藏沿用 `Library.favoriteLabel()`（「新增 N 集 · 更新至 M 集」），所以收藏更新資訊沒有丟。

## 頁頭隨滾動收起（2026-10-06）

列表向下瀏覽時，頁頭那一整塊（工具條上的品牌「紅果TV」、漫劇 / 短劇分類開關、右側搜尋 / 排行榜 / 設定入口，
以及二級頁自己的頁頭——搜尋行、榜單標題行、集合頁標題行）整體收起；回到列表頂部、或焦點回到頁頭裡的
任何控制元件時再展開。此前頁頭一直佔著螢幕最上面一條，向下翻列表時它和列表內容擠在一起，觀感很亂。

三條必須同時成立的觀感（排行榜 / 搜尋 / 首頁一致）：

1. **滾到中間時列表不會蓋住頁頭那一排按鈕**——裁剪由滾動容器的外殼提供（見上一節第 2 條），
   頁頭行與列表在同一個縱向容器裡上下排列，列表不可能畫到頁頭上面。
2. **向下滾頁頭收起**（200ms 高度動畫），**中間向上滾不會半路把頁頭彈回來**；
   只有回到列表最上邊（`y ≤ 12dp`）才展開，另外焦點落進頁頭裡的控制元件時立刻展開。
3. **同一頁原地追加（載入更多）時頁頭保持原來的收 / 展狀態**：使用者還在列表中間，
   追加一頁不應該把頁頭彈回來。換標籤 / 換分類這類換頁仍然從展開態開始。

實現放在 `MainActivity` 的頁頭收展三件套（`registerTopAreaRow()` / `onListScroll()` / `setTopAreaHidden()`）：

| 決定 | 原因 |
| --- | --- |
| 收起用**高度動畫**，不用 `translationY` | 收掉之後列表真的多佔這一條高度：頂部不會留下一條空白，也不會出現「按鈕浮在列表上面」的疊層 |
| 每行單獨記展開高度（`topAreaHeights`）與還原用的 `LayoutParams.height`（`topAreaRestore`） | 工具條是固定高度（`TvStyle.TOOLBAR_HEIGHT` 88dp），其餘頁頭是 `WRAP_CONTENT`，還原方式不一樣 |
| 收起時把這一行的 `clipChildren` 開啟、展開時立刻關掉 | 收起過程中子控制元件不能畫到行外；展開時又要讓焦點描邊畫得出來（見上一節） |
| 收展之後 200+120ms 內忽略滾動回呼（`topAreaSettleUntil`） | 視口高度變化會讓 `ScrollView` 回夾 `scrollY`，不設靜默期會在底部來回抖 |
| 焦點變化時檢查新焦點是否落在頁頭裡（`addOnGlobalFocusChangeListener`） | 收起的頁頭高度是 0，焦點落進去必須先展開，否則焦點停在看不見的按鈕上 |
| 恢復上次滾動位置的那一次滾動不計入（`restoringScroll` / `HomeScreen.restoring`） | 否則一進頁面頁頭就閃一下 |
| 展開只在「回到最上邊」或「焦點進頁頭」時觸發（`onListScroll()` 裡沒有「向上滾就展開」分支） | 列表中間向上滾時頁頭反覆彈出 / 收起會把畫面抖得很亂 |
| 「載入更多」這一次重建保留頁頭狀態（`keepTopAreaState`），新登記的行按收起狀態立刻擺好（`expandedHeightOf()` 先量基準高度） | 追加是同一頁的原地重建，使用者還在列表中間；不保留就會每追加一頁彈一次頁頭 |
| 重建期把 `topAreaSettleUntil` 往後推 200+120ms（`catalogGrid()` 開頭） | 重建自己會產生三次滾動（位置恢復、焦點回帶、內容夾取），它們不是使用者滾動，不能被當成「滾回頂部了」 |
| 位置恢復掛在列表的 `OnLayoutChangeListener` 上（`list.addOnLayoutChangeListener`），量完再用真實座標 `scrollTo` | 內容還沒測量時 `ScrollView.scrollTo` 的 `clamp` 裡 `my >= child` 直接返回 0：在 `post` 裡恢復等於把列表拉回頂部，頁頭跟著展開 |
| `TvStyle.animate=false` 的裝置直接到位 | 低配電視不排隊動畫，只保留結果 |

首頁劇架的滾動透過 `HomeScreen.onScroll` 上報，二級頁各自的 `ScrollView` 直接掛監聽，
兩處走的是同一個 `onListScroll()`，因此首頁和二級頁的行為一致。

### 收展動畫表必須先快照再取消（2026-10-06 修崩潰）

頁頭收展的動畫放在 `topAreaAnimators`（`View → ValueAnimator`）裡。原先頁面重建時寫的是
`topAreaAnimators.values.forEach { it.cancel() }`，這條邊遍歷邊刪的寫法會拋
`ConcurrentModificationException`：

- `ValueAnimator.cancel()` 會**同步**回呼 `onAnimationEnd`；
- 那條回呼裡 `topAreaAnimators.remove(row)` 正好從正在遍歷的這張表裡摘掉自己；
- `LinkedHashMap` 的迭代器在第二次 `next()` 時發現 `modCount` 變了，於是拋異常。

**頁頭只有一行時（首頁工具條）不會崩**：唯一那項被刪掉之後 `next` 已經是 `null`，
迭代自然結束、不會再校驗一次 `modCount`。**兩行以上（搜尋行 / 榜單標題行 / 集合頁標題行）必崩**，
而收展動畫的那 200ms 裡「展示更多 ↓」「重新整理榜單」、切分類、進詳情、返回列表都會走
`releaseCatalogViews()` 重建頁面——表現出來就是「下拉載入更多時偶發崩潰」。

修法：先把執行中的動畫快照成列表、清空表、再逐個 `cancel()`；同時把結束回呼裡的
「先判等再刪」改成原子的 `topAreaAnimators.remove(row) === this@apply`。
`tools/verify-button-system.py` 第 11 條按這個規則核對（反向注入舊寫法時腳本必須失敗）。

### 載入更多之後頁頭又展開（2026-10-06 修）

「下拉載入更多」之後頂部那排按鈕又冒出來，有三條獨立原因，都要堵：

1. **列表中間向上滾就展開**：舊 `onListScroll()` 裡有一條 `y < listScrollY - 4 → 展开`，
   追加一頁後回頭看新內容（向上滾）就會把頁頭彈回來。這條分支已按需求刪掉，
   只有回到最上邊（`y ≤ 12dp`）或焦點進頁頭才展開。
2. **重建期自己產生的滾動被當成使用者滾動**：列表重建會連帶產生三次滾動——位置恢復、
   焦點回帶（把新卡片帶回可見區域）、內容高度變化後的夾取。它們會走到 `onListScroll()`，
   其中「位置恢復」那一次尤其危險：內容還沒測量時 `ScrollView.scrollTo()` 的 `clamp()`
   裡 `my >= child` 直接 `return 0`，於是列表被拉回頂部，頁頭判定「滾到最上邊了」並展開。
   現在 `catalogGrid()` 開頭把 `topAreaSettleUntil` 往後推 200+120ms，並且把位置恢復
   掛到列表的 `OnLayoutChangeListener` 上（量完再用真實座標 `scrollTo`）。
3. **離樹控制元件當焦點目標**：頁頭行與底部按鈕都是新建的，如果 `moreButton` / `moreFocus`
   還留著上一頁的引用，焦點請求會落到已經離樹的控制元件上並失敗，焦點就可能被系統交回
   頁頭裡的第一個可聚焦控制元件，頁頭於是被重新展開。現在這兩者在 `catalogGrid()` 開頭就清空。
