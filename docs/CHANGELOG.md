## 1.0.7：下一集無感切換

### 修復

- **自動連播切下一集不再黑屏轉圈**：切集原先要把播放器停掉、清空播放列表再掛上新的一集，
  畫面因此掉到黑屏、編解碼器還要重建一次；新地址沒到手時更是要在空白畫面上等一整個請求往返。
  現在下一集**已經預熱好**時走無感路徑（見下一條）：不清播放器、不重建畫面，直接把新源頂上去，
  畫面停在上一集最後一幀上等下一集的第一幀；過渡期不顯示緩衝轉圈（上限 1.2 秒，真要走網路時
  該轉還得轉）；舊一集的影片與傳輸等新源出畫面之後再收（3 秒兜底）。
- **下一集預熱更靠譜**：預取視窗只有片尾 30 秒（`PrefetchPolicy.nearEnd`），而這條介面約一半
  機率回空回應；原先視窗內 15 秒才重試一次、最多 3 次，實際只來得及試兩次，兩次都空就只能
  退回「切集時現取播放地址」那條慢路——使用者看到的正是黑屏轉圈。現在改成 6 秒一次、最多 5 次。

## 1.0.6：帳號參數匯入、裝置註冊與相關作品介面

### 修復

- **手機掃碼匯入帳號參數報「來源不匹配」**：掃碼 App 的內建瀏覽器（微信 / QQ / 支付寶的 X5 核心）
  會把頁面套進自己的容器裡，提交時 `Origin` 變成 `null`、`Sec-Fetch-Site` 報成 `cross-site`，
  原先「`Origin` 必須與本機地址逐字元相等」加「`cross-site` 一律拒絕」兩條檢查於是把**自己人的
  瀏覽器**擋在門外。現在只攔能明確指認的第三方站點（`http(s)://` 且不是本機），
  認不出來源的放行；邊界仍由臨時埠、128 位隨機地址、15 分鐘時限、一次性消費與
  區域網來源判定守住。
- **未登入時「我的」頁焦點下不到「匯入帳號參數」**：導航欄那排圓形入口（以及同在一行的
  收藏 / 歷史 / 點贊 / 預約晶片）的「按下鍵」原先落在同一視覺行的晶片上，內容為空時
  也沒有後續接線能改它，焦點只能在導航欄那一行裡打轉。現在它們統一落到導航欄正下方的
  身份行（未登入時就是「匯入帳號參數」）。
- **相關劇集不再等 2~4 秒**：原先「同系列各季」是拿劇名去官網搜尋近似召回——沿季號逐季搜
  （1 到「當前季 + 2」每個季號中文 / 阿拉伯各一次）、基名與去尾字各搜一次、再掃 6 頁片庫目錄，
  二十多次請求、實測 2~4s，召回還不穩定（同一部劇的某一季有時在前 10、有時不在）。
  現在改用 App 詳情頁那一欄自己的介面 `GET /reading/bookapi/plan/v:version/`
  （`scene=10&from=detail_page_more_related&book_id={剧集 ID}`）：**一次請求拿全**，
  實測 0.4~1.1s（含空回應換線重試），並且平臺自己給了 `season_index`。

### 變更

- **播放只用平臺註冊過的裝置身份**：`device_id` / `install_id` 不再有「本機隨機值」這一路，
  唯一來源是匿名註冊（`device_register`）下發的那一對。啟動時非同步註冊一次，**取播放地址
  之前再同步兜一次**（取地址與下一集預取兩條路），預取另開的那個倉庫例項也共用同一份身份
  與註冊 Cookie。註冊沒落地時不再拿隨機值簽名，也不會落到內建那份被平臺拉黑的檔案上。
- `ContentRepository.related(id, title)` 改為讀「相關作品」cell（`show_type=547`）的
  `video_data[]`；同系列仍按劇名（`SeriesSeasons.normalize`）篩、按季號升序排在前面，
  其餘條目接在後面並按劇集 ID 去重，正在看的那一部不出現。
- 那一欄另按劇集 ID 快取（`RELATED_CACHE_LIMIT`，16 條）：看一集回簡介再點開不再打介面。
- 官網詳情頁的 `recommendationGroups.related_list` 退居**兜底**（介面整輪失敗時用），
  不再觸發任何搜尋與片庫目錄掃描；`SEASON_*` 那一套常量與執行緒池隨之刪除。
- 介面把劇名一起傳下去（`repository.related(id, detail?.series?.title)`），core 不必再取一次詳情。

### 說明

- 這個介面約一半機率回 **HTTP 200 + 0 位元組**（與裝置是否註冊無關），客戶端按六條線路輪換重發、
  最多 8 次；`ads5-normal-*.zijieapi.com` 不認這個介面（實測 0/6），不在候選裡。
- 不能只看 `tag_info`（`第N季` / `同IP`）挑同系列：`第N季` 那一組裡混著同 IP 的另一個系列
  （萬妖圖錄傳第一季那頁有「萬妖圖錄傳：月落鎮魔第二季」）。篩選規則仍是按劇名歸一化比對。
- 協議、欄位、坑見 [HONGGUO_API.md](HONGGUO_API.md) 4.6。

## 1.0.3：長文字彈窗改為滾動，按鈕不再被頂出畫面

更新日誌、開源許可這類正文很長，彈窗的內容區原先**既不封頂也不滾動**，一長就把
按鈕行頂出畫面——使用者看得到日誌、卻看不到「更新 / 暫不更新」。

### 修復

- 彈窗的內容區加上「封頂 + 滾動」：超出部分在內容區裡滾動，按鈕行始終留在畫面裡。
- 內容區與列表區**共用一份高度預算**（螢幕高度的 50%），兩塊同時出現時
  （備份恢復：說明文字 + 選項）加起來也不會頂出一屏；只有一塊時那一塊獨佔，
  短內容按自然高度擺、不封頂，觀感與以前完全一致。
- 只有內容真的溢位時內容區才進焦點鏈：此時按鈕行按上鍵進正文區上下滾動、
  按下鍵回按鈕行；內容裡有可聚焦控制元件（備份恢復那個開關）時焦點交給控制元件自己，
  `ScrollView` 會把它滾進可視區。
- 上下焦點餘量只在內容裡真有可聚焦控制元件時才留——純文字彈窗（更新日誌、開源許可、
  二次確認）不再白佔那 14dp。

**受益的彈窗**：更新提示（發現新版本）、設定 →「版本與更新」的狀態框、
設定 →「開源許可」（約 15 行正文）、備份與恢復的確認框。這些走的是同一個
`TvDialog` 內容區，一次改動全部生效。

### 修復

- **榜單 / 分類首次進入的預設選擇與落點**：本次執行第一次進分類頁預設「漫劇 · 全部」、

- **榜單 / 分類的焦點**：點哪一枚晶片，焦點就留在那一枚上（不再跳到內容第一張卡，
  也不再「選完二級分類先跑到一級分類」）。為此換榜單 / 換分類時不再清空列表——
  舊的一屏留在原位等新資料落地，觀感上不再「每次選分類都閃一下」。

- **首頁按返回**：首頁按返回鍵直接彈退出確認。原先先把焦點搬到頂部圓形入口再等第二次返回，

- **榜單 / 分類「載入更多」接不上最後一行**：一頁 20 部按六列切開時最後一行只有 2 張、
  後面 4 個槽位是空槽；追加下一頁時視窗範圍沒變，那一行不會重綁，

- **首頁劇架最右邊進不去榜單**：同上一條的入口問題，行末「檢視全部」與右鍵兩條路徑都已核對。

- **封面快取重做**：磁碟快取從「存原圖」改為「存已經縮到卡片尺寸的 WebP」

  根治了「載入幾百個卡片之後越來越卡」。

## 0.15.1：彈幕裡的表情標籤還原成表情圖

平臺的彈幕裡表情不是字形，而是方括號包起來的名字：`[笑哭]`、`【赞】`、`［狗头］`。
以前照原樣畫出來，螢幕上就是一串 `[笑哭]` 文字；這一版把它們還原成表情。

- 包名 `com.hongguotv.nativeapp`，versionCode 22，versionName 0.15.1，最低 API 26 / 目標 API 36。
- 產物：`outputs/hongguotv-kotlin-0.15.1-android8.apk`（debug 包為 `hongguotv-0.15.1-debug.apk`）。
- 簽名與 0.9.x–0.15.0 相同，可直接覆蓋安裝；本機收藏 / 歷史 / 設定保留。

### 1. 三層對應：標籤名 → 字形 → 圖片

```
[笑哭] ──标签表──▶ 😂 ──图片表──▶ 1f602.webp ──▶ 画在画布上
```

- **標籤表**（`core/.../DanmakuEmoji.kt`）：231 條名字 → 字形。同一張臉在平臺上有很多叫法
  （`笑哭` / `大笑` / `爽`），都收在同一張表裡；名字大小寫不敏感（`OK` / `okk`）。
- **圖片表**：144 個字形 → 檔名，檔名就是碼位（`1f602.webp` = 😂，`2764-fe0f.webp` = ❤️）。
- **圖片**：`app/src/main/assets/danmaku_emoji/`，Microsoft Fluent Emoji 轉 128px WebP，
  144 張共 592 KB（原 PNG 是 5.3 MB）。許可證隨圖放在同目錄 `LICENSE.txt`（MIT）。

### 2. 標籤識別

三種括號都認：半形 `[名字]`、全形 `［名字］`、`【名字】`。名字 1–16 個字元，且不含任何括號與換行。

這樣幾條邊界是對的：

| 輸入 | 結果 | 為什麼 |
| --- | --- | --- |
| `前面高能[笑哭]` | `前面高能😂` | 正常標籤 |
| `[不存在]高能` | 原樣保留 | 認不出的名字不吃字 |
| `看到第[3]集` | 原樣保留 | 正文方括號大多認不出名字 |
| `[前面[笑哭]` | `[前面😂` | 名字裡不允許出現括號，外層不匹配、裡層照常換 |
| `[笑哭\n]高能` | 原樣保留 | 換行把標籤截斷 |

### 3. 一個表情可能不止一個碼位

`✌️` 帶變體選擇符、`😮‍💨` 用 ZWJ 連、`👉👈` 是兩個表情並排。切片段時按**字形簇**切，
整簇一起查表——按碼位切會拆出半個表情，把兩張圖疊在一起。

正文裡本來就打出來的 emoji（`哈哈😂`）一樣能認出來：表按字形給，不要求先有標籤。

### 4. 彈幕層的畫法

`DanmakuView` 的每條彈幕從「一段文字」變成「文字片段 + 表情片段」：

- 寬度 = 文字按字型量 + 表情按 `1.2 × 字号` 算；表情圖貼著文字行中線居中
  （按基線直接畫會整體偏上）。切片段只在整批重排軌道時做一次，每幀只按播放位置求 x。
- 圖還沒解好時**退回畫字形**（片段裡就存著字形），寬度早已按圖片邊長算過，
  所以換成圖片之後這條彈幕的位置和長度都不會跳。
- 表情圖跟著彈幕透明度一起淡：字淡了、表情還是全綵，看上去就像貼上去的貼紙。

圖片解碼在 `DanmakuEmojiStore` 裡：固定 128px 解碼（字號是使用者 0.6–2 倍滑出來的，
跟著字號解碼會為每個縮放檔位各存一份點陣圖），LRU 封頂（低記憶體裝置 4 MiB、其餘 8 MiB），
整批重排時先把這一集用到的表情排進解碼佇列，螢幕上不會先閃字形再換圖。

### 5. 本版驗證

- `./android/gradlew -p android --offline :core:test`：全綠。新增 `DanmakuEmojiTest` 9 項：三種括號、認不出的名字
  原樣保留、大小寫、多碼位表情整簇、正文裡的 emoji、並排雙表情，以及**逐條核對 231 個標籤都能

### 6. 修復：所有影片都放不了（平臺改了播放介面路徑）

現象：這一版（以及**未改動的 0.11.0 基線**）所有影片都打不開，提示「播放介面暫不可用」。

原因在平臺側，不在客戶端改動：播放介面從

```
POST /novel/player/multi_video_model/v1/            ← 旧路径，现在一律返回 Code 110001 未知异常
POST /novel/player/multi_video_model/:dr_scene/v1/  ← 现在要带场景段
```

改成了帶場景段的形式（路由表裡本來就是這兩條，`:dr_scene` 之前可以省略、現在不能）。
實測同一份請求體：舊路徑 `110001`，`.../default/v1/` 與 `.../detail/v1/` 都返回 `code 0` 與完整的
`video_model`。六條線路（a/b/c/lf/lq/hl）表現一致，逐檔版本號（7.1.3 → 7.4.2）也一樣，
所以與線路、與 App 版本都無關。

修法（`ContentRepository.videoModel`）：按 **`default` → `detail` → 舊路徑** 的順序試，
第一個業務成功（`code == 0` 且 `data` 非空）的就用；全失敗時拋最後一個錯誤，
介面照常顯示「播放介面暫不可用」。舊路徑留在最後，灰度環境或平臺回滾時還能用。

迴歸測試三條（`ContentRepositoryTest`）：優先帶場景段的路徑、帶場景段全失敗時退回舊路徑、
三條路都只有業務錯誤碼時如實報錯。聯網複測：`quality=1080P; total=28974608; header=ftyp`
（真實 1080P 分段可讀）。

### 7. 彈窗按鈕不再「常亮」、二級分類小一檔

**彈窗裡的按鈕一律常態外觀。** 之前「確認 / 知道了 / 手機填寫 / 合併恢復」用的是 PRIMARY——
PRIMARY 是「常亮的亮面板」（給詳情頁主操作用的，一屏最多一個），放進彈窗裡看起來就像
**一直處於焦點**，退出確認時容易誤以為焦點已經落在「確認」上。現在彈窗裡全部改用常規檔，
靠文案區分動作；焦點落點不變（列表型彈窗落在第一項，其餘落在第一個按鈕）。

**分類頁的二級分類（小類）整體小一檔。** `ToggleChip` 增加尺寸檔參數，
分類頁的大類用預設檔（高度 48dp / 字號 16sp / 左右內邊距 28dp），小類用緊湊檔
（40dp / 15sp / 18dp），小類那一行的行內間距也收一檔。兩行大小不同，一眼能看出層級。

## 0.12.4：相關劇集改成懶載入，並儘量把同系列各季找齊

0.12.3 把「同系列各季」掛在了詳情介面上，導致每次進簡介頁都要多等幾次搜尋；這一版把它挪到
「相關劇集」按鈕裡，並換了召回更好的取數方式。簽名與 0.9.x–0.12.3 相同，可直接覆蓋安裝。

- 包名 `com.hongguotv.nativeapp`，versionCode 19，versionName 0.12.4，最低 API 26 / 目標 API 36。
- 產物：`outputs/hongguotv-kotlin-0.12.4-android8.apk`。

### 1. 懶載入：詳情先上屏，相關劇集後臺預取

`Detail` 不再帶 `related` / `seasons`（改由 `RelatedWorks` 單獨返回）。流程是：

1. 點進簡介頁 → 只等詳情，**內容立刻渲染**（實測 458–522ms）；
2. 詳情落地的那一幀就把相關劇集丟到後臺去查（`prefetchRelated`，2~4s 跑完，介面無感知）；
3. 使用者點「相關劇集」時**不再發新請求**——取好了直接鋪；還在途中就等它落地
   （這段時間介面顯示「正在查詢同系列…」，通常察覺不到）；同一部劇不會重複請求
   （`relatedFor` 擋住重複，失敗後使用者再點開才補一次）。

失敗顯示「相關劇集載入失敗」+「重試」按鈕，不再靜默空列表。

這條請求**不走 `work`**：`work` 會取消上一次在途請求（詳情頁重排、切集都會觸發），
相關劇集的結果會被自己頁面的重排取消掉，永遠停在載入態。因此它單獨持有
`relatedToken` + `relatedJob`，結果落地前再確認「還是同一部劇、還停在詳情頁」。

### 2. 召回：沿季號逐季搜尋 + 三路合併

官網搜尋一次只回 10 條、且**忽略所有分頁參數**（實測 `?page=2/3`、`?page_num`、`?offset`、
`?pageNo`、`?p`、`?limit` 全部同一批），但**換關鍵詞就是換一批**。於是取數改成：

| 手段 | 說明 |
| --- | --- |
| **沿季號逐季搜** | 搜 1 到「當前季 + 2」的每個季號（`第三季` → `第四季` → `第五季`…）。**不能只往上搜**：當前是最新一季時，更早的那幾季只能靠搜它們自己的季號命中；每個季號帶回的 10 條裡往往包含好幾個季，逐個搜一遍就都覆蓋到了。中文寫法優先，整輪無命中才補一輪阿拉伯寫法 |
| 基名與去尾字 | 基名本身搜一次（第 1 季的劇名常常就是基名），再去掉 1~3 個尾字各搜一次 |
| 片庫目錄掃描 | `/category/real-drama?page=N` 每頁 24 部、共 34 頁，穩定分頁，是召回的最後一道保險；最多 6 頁 |
| 併發 | 這些請求彼此獨立，二十多個序列要一分多鐘（實測 1m49s），因此走 4 路 `relatedPool` 併發，整輪約 2~3s |
| 歸一化篩選 + 按季號排序 | 剝季號、全形轉半形、去標點後完全相同才算同一系列，再按季號升序 |

實測（同一部劇三次跑）：

| 劇集 | 0.12.3（只搜基名） | 0.12.4 | 耗時 |
| --- | --- | --- | --- |
| 聚寶仙盆之雜靈根才是真BOSS第十三季 | 8 季 | **13 季全** | 2.6s |
| 一夢青玄，團寵小師妹一劍毀天滅地第七季 | 5 季 | **7 季全** | 2.1s |

### 3. 簡介頁按鈕行：四個入口等寬，播放鍵不再常亮

### 4. 不再彈系統 Toast

應用裡**不再彈 Toast**（`MainActivity` 裡 `Toast.makeText` 已全部移除，dex 裡 0 處引用）。
Toast 是獨立於介面的一層浮窗：樣式、字號、焦點行為都不受本應用控制，電視上還會蓋在畫面正中。

逐處處理方式：

| 原 Toast | 現在 |
| --- | --- |
| 熱門已更新 / 重新整理失敗 / 載入更多失敗 / 搜尋結果已過期 / 記錄已合併恢復 | 改為**頁面內提示行**（頁頭下面一行淡字，不參與焦點、4 秒後自己消失，頁面重建時按狀態復原） |
| 正在更新熱門… | 只在沒有快取可顯示時才提示；有快取時頁面本身就是「上次內容」 |

## 0.12.3：相關劇集改成「同系列各季 + 相關短劇」

上一版的相關劇集取的是官網詳情頁的推薦位（`related_list`），實測那不是同一部劇的其它季。
這一版把「同一部劇的其它季」排在前面（按季號升序），後面再接原來的相關短劇，重複的去掉。
簽名與 0.9.x–0.12.2 相同，可直接覆蓋安裝。

- 包名 `com.hongguotv.nativeapp`，versionCode 18，versionName 0.12.3，最低 API 26 / 目標 API 36。
- 產物：`outputs/hongguotv-kotlin-0.12.3-android8.apk`。

### 1. 平臺沒有分季介面（實測）

| 位置 | 結論 |
| --- | --- |
| `seriesDetail` 全欄位 | 只有當前這一季，沒有 season / series_group / album 欄位 |
| `recommendationGroups.related_list` | 「看了這部還看什麼」的推薦，不是同系列 |
| `recommendationGroups.hot_list` | 同頁熱門欄，與本劇無關 |

能拿到同系列的入口只有一個：**用劇名去官網搜尋**。實測搜「聚寶仙盆」時，同一系列的
7 季都排在第 1 頁 10 條裡；搜全名時前 10 條全是本系列。

### 2. 做法

`core/SeriesSeasons.kt`（純邏輯，6 項單元測試）：

1. **基名**：剝掉劇名尾部季號——`第X季` / `第X部` / `X季` / `SX` / `Season X`，
   中文數字（`十三`）與阿拉伯數字（`13`）都認；`第一季` 歸一為第 1 季，沒有季號算第 1 季；
2. **歸一化比對**：候選劇名同樣剝季號、全形轉半形、去空白與標點後與基名完全相同才算同一系列
   （否則 `咱家剑宗团宠小师妹第五季` 會被當成 `一梦青玄，团宠小师妹一剑毁天灭地` 的兄弟）；
3. **排序**：按季號升序，季號相同按劇名兜底。

`ContentRepository.seasonSiblings()` 用基名走官網搜尋，最多翻 3 頁（一頁約 10 條，
第 2 頁起是片庫目錄掃描，按 id 去重），再用上面的規則篩出同系列。

`relatedFor()` 把兩段合併：**同系列各季在前，`related_list` 的內容在後，重複的按劇集 ID 去掉**
（正在看的那一部本身也不重複出現）。`Detail` 因此增加 `seasons` 欄位，介面據此標註季號。

### 3. 介面

- 標題按有沒有同系列區分：「**同系列 N 季 · 相關劇集**」/「相關劇集」；
- 同系列的卡片在**海報右下角標**上寫「第 N 季」，正在看的那一季寫「正在看」
  （狀態行那點字號讀不出季數）；
- 點其它季的卡片直接進那一季的簡介頁；空列表時仍顯示「這一部暫時沒有相關劇集」。

### 4. 驗證與邊界

- `:core:test` 全綠（新增 `SeriesSeasonsTest` 6 項：季號解析、中文數字、無季號按第 1 季、
  歸一化、同系列篩選與排序、空輸入）；
- `--related` 探針實測：
  `聚宝仙盆之杂灵根才是真BOSS第十三季` → 同系列 8 季（第 1 / 4 / 5 / 6 / 7 / 10 / 11 / 13 季，
  升序、無別的劇混入）+ 相關短劇，合併後 24 條且無重複；
  `帐中香` → 同系列 1 季（就是它自己）+ 相關短劇 16 條；
  探針內建斷言：升序、不混入別的劇、無重複條目、同系列排在前面；
- `:app:lintRelease` 無 error；`:app:assembleRelease` / `:app:assembleDebug` 透過；
- 文件：`docs/HONGGUO_API.md` 新增 3.4.2 節（做法 + 實測證據 + 侷限），
  `README.md` 頂部版本與本節同步。

**侷限（如實記錄）**：劇名寫法不統一時會漏掉或混入——改名、副標題變化、外傳與正片同名都算；
平臺把同一系列拆成不同基名（`聚宝仙盆仙界篇` 與 `聚宝仙盆之杂灵根才是真BOSS`）時也會各算一系列。
因此這一欄做的是「同系列各季 + 相關短劇」的合併列表，而不是嚴格的分季樹。

## 0.12.2：簡介頁「相關劇集」

簡介頁新增一欄「相關劇集」，資料取自官網詳情頁同一份 HTML 裡的相關短劇列表。

- 產物：`outputs/hongguotv-kotlin-0.12.2-android8.apk`。

### 1. 相關劇集的資料來源

官網詳情頁 `GET /detail?series_id={id}` 的 HTML 裡有兩段資料：

1. `_ROUTER_DATA.loaderData.detail_page.seriesDetail` —— 現有的詳情（`vid_list` 等），**不含相關作品**；
2. `<script data-fn-name="mergeLoaderData" data-fn-args="…">` —— 相關短劇的增量資料。參數是 HTML
   實體轉義過的 JSON 陣列 `["detail_page",[{key:"recommendations", routerDataFnArgs:["<JSON>"]}]]`，
   內層 JSON 是 `{videoList, recommendationGroups:{hot_list, related_list}}`。

客戶端取 `recommendationGroups.related_list`（實測 16 部，欄位與 `Card` 同構），缺失時退回

解析實現在 `ContentRepository.extractRecommendations` / `relatedOf`，`Detail` 增加 `related` 欄位，
詳情頁因此**一次請求**就能拿到兩者（不再多發一次）。

聯調：`./android/gradlew -p android --offline :core:run --args="--related <剧集ID>"`。

### 2. 互動與佈局

- 「**相關劇集**」按鈕排在「完整簡介」之後，與「開始觀看 / 收藏」同檔同高（56dp）；

- 相關作品沿用首頁劇架的卡片（豎版海報 + 劇名 + 狀態），橫向可滾動，左右選片、確認進那一部的簡介頁；
  長按 / 選單鍵的卡片選單也在（詳情頁上不出現「不在熱門推薦中顯示」這一項）。
- 焦點：按鈕行按下鍵落到相關作品第一張卡，卡片按上鍵回到「相關劇集」按鈕；收起時這套指向改回選集網格。
- 介面沒給相關劇集時顯示「這一部暫時沒有相關劇集」，不留空白。

### 3. 驗證與邊界

- `:core:test` 全綠；`:app:lintRelease` 無 error；`:app:assembleRelease` / `:app:assembleDebug` 透過。
- `--related` 探針實測：`聚宝仙盆之杂灵根才是真BOSS第十三季` 與 `首辅娇娘` 各 16 部，兩次請求結果一致。

## 0.11.0：彈幕看得見、播放介面更安靜、播放設定收進下方三分之一

本版把「彈幕」這條路從「介面能取到資料」推進到「螢幕上真的看得見、能調大小與濃淡」，
並把播放設定面板收進螢幕下方三分之一。簽名與 0.9.x / 0.10.0 相同，可直接覆蓋安裝，
本機收藏、進度、主題與播放偏好全部保留。

### 1. 彈幕不顯示：根因是檢視可見性把自己鎖死了

`DanmakuView` 原來在排軌道之前先把空態設成 `GONE`。`GONE` 的檢視**不參與測量**，
於是 `width`/`height` 永遠是 0，「有寬高才排軌道」的條件永遠不成立，
介面就算返回幾千條也一條都畫不出來——表現和「彈幕功能沒生效」完全一樣。

現在的規則：

- 空態用 `INVISIBLE`（照樣被測量、被佈局，只是不繪製），取到彈幕時能立刻按真實尺寸排軌道；
- 可見性只按「這一集有沒有資料」判斷（`mode==HIDDEN || raw.isEmpty()`），不再按「排沒排成軌道」判斷，
  兩個條件不再互相等待；
- 每換一集 `danmakuToken` 自增一次，在途的視窗迴圈發現 token 變了立刻收手，舊劇的彈幕不會接到新一集上。

### 2. 邊拉邊畫：不再等整集拉完才出第一條

整集要按 30 秒視窗連著拉幾十頁，視窗之間還有 180ms 頻控間隔，整集拉完要十幾秒。
等全量再畫等於前十幾秒一條彈幕都沒有。`ContentRepository.danmaku` 因此增加
`onWindow` 回呼，每到一個視窗就交給主執行緒先鋪上屏（帶 token 校驗，切集後到達的舊視窗直接丟棄），
整集拉完再替換成完整的一份。

### 3. 彈幕稀疏是平臺行為，不是參數問題（實測結論）

模擬器上裝了抓包工具與紅果短劇，請求被斷開、拿不到有效資料，於是改成在系統 CA + Frida 掛鉤
`SSL_write`/`SSL_read`（命中 `libsscronet.so`、`libttboringssl.so` 等 11 個庫，回應是 brotli）。
**決定性證據**：原版 App 對同一集也只收到 `total: 2`，5 個視窗只有視窗 0 有資料；
用抓到的請求體逐欄位回放，結果一樣是 2 條。

結論：介面對匿名裝置返回的是**取樣後的熱彈幕**，與請求參數無關，`cursor` 裡的
`danmaku_count` 也不是彈幕條數。表現就是「有的劇一屏彈幕、有的劇一條都沒有」——
同一部劇的另一集實測拿到 114 條。播放介面的狀態行會直接報出這一集取到多少條，
`adb logcat -s HongguoTV` 裡也有一行 `Danmaku episode=... count=...`，
便於區分「這一集本來沒有彈幕」和「彈幕功能沒生效」。

### 4. 播放時螢幕上只剩畫面與彈幕

- **頂部標題條預設收起**：整寬 96dp 的「劇名 · 第幾集 + 時鐘」原來一直壓在畫面上，
  現在只在喚出播放介面時出現（底部控制條、播放設定面板、選集面板、播放失敗介面都會把它帶出來），
  收起時整條 `GONE`，不佔畫面也不參與繪製。
- **上方彈幕只佔最上面四分之一**：`TOP` 檔的可鋪區域從「約三分之一」收到 `0.25`，
  離頂邊的安全邊距從 104dp（標題條高度）收到 20dp，留白全放在下面，
  彈幕整體往上走、不再壓畫面正中；`FULL` 檔仍然是整幅畫面，只讓開標題條與底部控制層。

### 5. 播放設定面板收進下方三分之一，多出來的滑出來

面板原來是「內容多高就多高」，七行鋪下去會佔掉大半個螢幕。現在：

- 整寬貼在畫面下方，**高度鎖死為螢幕高度的三分之一**（`heightPixels/3`）；
- 裝不下的行留在滾動容器裡，遙控器焦點走到哪一行就自動把哪一行帶進可視區
  （`ScrollView` 自身的 `requestChildFocus` 行為），七行全都按得到；
- 漸變背板畫在外殼上而不是面板上：否則背板會跟著內容一起被拉長，滾到下半段時面板頂部會變成半黑，
  而不是「從透明漸漸暗下去」；外殼同時負責裁剪，面板內容不會畫到面板之外；
- 行號收斂成常量（`MENU_ROW_*`）：面板裡幾處「改完就地重畫這一行、再把焦點按回同一格」的呼叫
  原來寫死數字，中間插一行就會全部錯位。

### 6. 新增「字幕大小」「字幕透明度」兩條滑動調節

播放設定面板與設定頁都加了這兩條，改的是同一份本機偏好，進播放介面立刻生效：

| 專案 | 範圍 | 步長 | 預設 |
| --- | --- | --- | --- |
| 字幕大小 | 60% – 200% | 10% | 100% |
| 字幕透明度 | 20% – 100% | 10% | 100% |

滑動條複用全站緊湊檔按鈕的外觀與焦點體系（凸起 / 打亮 / 按進去三態、膠囊圓角、同樣的柔光帶），
裡面畫軌道、已選填充 + 圓鈕、右對齊的百分比讀數。**不用 `SeekBar`**：
電視上 `SeekBar` 會自己搶焦點、自己處理左右鍵，和麵板的四向鎖定打架。
這裡左右鍵由控制元件自己在 `onKeyDown` 裡吃掉（按一下走一檔、長按連續走），上下鍵仍然交給焦點系統。

值統一由 `DanmakuStyle`（core）歸一：先吸附到 0.1 的整數倍、再夾進上下限、最後抹掉浮點誤差，
因此「面板上滑到的數」「寫盤的數」「下次讀回來的數」是同一個浮點值，
不會出現顯示 130% 卻和 130% 不相等這類抖檔。字號變化會重排軌道（行距跟著字號走），
透明度只改畫筆 alpha、不重排；描邊的不透明度跟著文字一起縮，字淡了不會留一圈黑邊。

### 7. 相容與驗證

- 設定鍵新增 `danmakuScale` / `danmakuAlpha`；備份檔案新增 `danmakuScale` / `danmakuAlpha` 兩個欄位，
  **舊備份沒有這兩個欄位時按 100% 讀回**，越界值直接夾進合法區間，舊檔案仍然可以恢復。
- `:core:test` 全綠，新增用例覆蓋「兩個欄位的備份往返」「舊備份缺欄位按 100% 讀回」
  「越界值夾進區間」「百分比讀數」。
- Android 12 模擬器（1440×2560 / 360dpi，橫屏 2560×1440）上實測：面板固定在下三分之一、
  滾動可達全部七行、兩條滑動條左右鍵連續調節、彈幕字號與濃淡立刻作用在畫面上。

Android 8 實體電視的遙控器手感、4K 畫布下的彈幕字號上限、以及長時間播放的穩定性仍需實機確認。

暫停時動畫迴圈停下、繼續播放時由 `onIsPlayingChanged` 叫醒。頂部 104dp（標題條）以下、
底部 120dp（控制層）以上才是彈幕區域，單幀最多畫 160 條。

### 2. 搜尋：漫劇不再報錯，結果改成向下自動載入

- **漫劇搜尋報錯的根因**：App 搜尋介面 `GET /reading/bookapi/search/tab/v` 現在對匿名裝置返回
  **HTTP 200 + 空回應體**（六條線路、多組裝置參數、GET / POST、全新裝置標識都一樣，
  `danmu_api` 的獨立簽名實現同樣拿不到資料）。舊程式碼把空 body 直接丟給 `JSONObject`，
  拋的是 `A JSONObject text must begin with '{'`，而短劇還有一條「退回官網搜尋」的兜底、漫劇沒有，
  於是漫劇搜尋只剩一句錯誤提示。現在先判空、再退回官網搜尋，漫劇和短劇走同一條路。
- **翻頁改成向下追加**：搜尋頁去掉「上一頁 / 下一頁」，改成和熱播榜、熱門集合頁同一套
  「往下接」機制——滾到接近底部（或焦點走到最後兩行）就靜默取下一頁，接在列表末尾，
  視口上方的畫素一個都不動，因此不會跳回頂部。底部只留一行不可聚焦的進度文字。
- **「更多結果」從片庫目錄補**：官網搜尋不區分內容型別、也**沒有分頁**——`?page=2`、`page_num`、
  `offset`、`page_size`、`count` 等參數全部被忽略，一次只給前 10 條（`totalCount` 顯示有 200 左右）。
  所以搜尋被拆成兩段：

  | 位置 | 來源 | 說明 |
  | --- | --- | --- |
  | 第 1 頁 | App 搜尋介面；拿不到資料時退回官網搜尋 | App 介面一次 20 條、按內容型別分 tab；官網搜尋最多 10 條，按相關度 |
  | 第 2 頁起 | App 搜尋介面的遊標；介面不可用時退回片庫目錄（`/category/comic-drama` / `/category/real-drama`） | 目錄 24 部一頁、各 34 頁，每次往後掃 3 頁，只留下**片名含關鍵詞**且**介面還沒見過**的劇 |

  實測「修仙 · 漫劇」（匿名）：10 + 2 + 4 + 4 + 1 = **21 條**，滾到底再收；「聚寶 · 漫劇」：10 + 1 條後收手。
  目錄翻完、或者連續一輪一個新條目都沒有，`hasMore` 就收掉——不會讓使用者一直往下滾卻什麼都沒有。
  同一部劇的不同季、目錄分頁本身的重複都由「已發過名單」擋掉，介面不會看到重複卡片。
- **可選登入態（2026-10-09 複測後新增）**：設定 → 片單與裝置 → 「搜尋登入態」，用手機掃碼貼上
  App 抓到的 `x-tt-token`（整段 Cookie 也可以）。填上後 App 搜尋介面按該帳號返回資料，
  搜尋第 1 頁起就直接用它（一次 20 條、按短劇 / 漫劇分 tab、可繼續翻頁），不再依賴官網搜尋與片庫目錄。
  口令只存在本機（`native-session-v1`）、只用於搜尋請求，不進備份檔案、不上傳；清除口令即回到匿名請求。
  **不填也能搜尋**：退回官網搜尋 + 片庫目錄補頁，這是預設路徑。
- **翻頁改成向下追加**：搜尋頁去掉「上一頁 / 下一頁」，改成和熱播榜、熱門集合頁同一套
  「往下接」機制——滾到接近底部（或焦點走到最後兩行）就靜默取下一頁，接在列表末尾，
  視口上方的畫素一個都不動，因此不會跳回頂部。底部只留一行不可聚焦的進度文字。
  遊標缺失或過期時回到第 1 頁重新搜（提示「搜尋結果已過期，已回到第 1 頁重新整理」）。
- **搜尋框不再困住焦點**：輸入框是 `EditText`，方向鍵會被它的游標移動邏輯吃掉，焦點回到搜尋框後
  上下鍵就出不去。現在這兩下顯式交回頁面：上=分類開關（短劇 / 漫劇），下=搜尋結果第一張卡
  （沒有結果時退到頂部入口）。

最低 Android 8.0 / API 26，包名 `com.hongguotv.nativeapp`，versionCode 6。單 APK，聯網即用，無需 Docker 或額外服務；沿用釋出簽名，覆蓋安裝 0.5.0 可保留本機記錄。

### 本版變化

1. **首頁按觀看任務組織**：接著看、收藏有更新、稍後看、熱門發現，各自橫向選劇。空分割槽自動隱藏；接著看顯示集數、時間和進度條，確認直接續播。收藏更新展示具體劇和新增集數，熱門更多頁保留原有分頁。
2. **選劇資訊隨焦點展示**：首頁及搜尋/排行榜/收藏/歷史頂部顯示選中劇的劇名、介面提供的集數或熱度、題材和簡介，並補充已收藏、稍後看、觀看位置等本機狀態。長簡介可進入詳情展開。720p、1.5 倍字型下縮小封面，為文字留出空間。
3. **劇卡快捷操作**：長按確認或選單鍵直接播放/續播、收藏、稍後看、檢視詳情；首頁可隱藏熱門推薦，設定可一鍵恢復。稍後看 100 部、隱藏推薦 500 部納入備份，舊版備份缺少這些欄位時仍可恢復。
4. **啟動與切集最佳化**：首頁後設資料快取 7 天，封面快取最多 24 MiB，按焦點附近載入。後臺新內容由使用者確認替換，避免移動正在瀏覽的卡片。下一集在自動連播開啟、非按流量計費網路、當前播放穩定且已緩衝至少 5 秒時預載入；只保留一個準備結果和最多 1 MiB 開頭，2 分鐘失效，不落盤。影片索引繼續受原有 8 MiB 上限約束。切換清晰度、退出/後臺或網路丟失/轉為計費時取消；失敗/過期/未完成走正常解析和恢復流程。

### 驗證

- 56 項 JVM 測試透過，0 失敗、0 跳過。新增測試覆蓋首頁快取損壞/過期/時鐘回退、備份欄位相容、預載入單次交接/清晰度不匹配/遲到結果取消，以及真實本地 HTTP Range 請求的字首複用和跨快取邊界讀取。
- Release lint：0 錯誤、25 警告；保留舊版相容性與依賴提示，新增程式化 View 構造器和中文文字拼接提示，不涉及最低 API 相容錯誤。
- 正式簽名 APK 在 Android TV API 36 ARM64 模擬器上驗證：覆蓋安裝保留記錄，遙控器跨分割槽/橫向滾動、長按與選單鍵、取消恢復焦點、收藏更新分割槽、稍後看持久化、隱藏/恢復推薦、720p 大字型完整卡片、真實 HTTP 備份匯出/確認恢復，以及連續 9 次前後換集。
- 收藏更新測試使用人為減小 3 集的歷史基準，再由正式 APK 查詢真實介面；這用於驗證新增提示，並非等待實際內容釋出。
- 備份往返核對稍後看、收藏、觀看位置和設定均保留，隱藏推薦匯出後可由設定清除。
- 驗證 ZIP 含正式包 SHA、截圖/XML、日誌、測試與 lint 報告。`tools/verify-discovery-evidence.py` 檢查儲存的證據，不替代實機測試。

### 效能樣本

# Kotlin TV 0.5.0

基於遠端 `3c2acd7` 繼續迭代，包名 `com.hongguotv.nativeapp`，versionCode 5，最低 Android 8.0 / API 26。仍為獨立 APK，無需部署第二套服務。

### 這次補齊的功能

- 定時停止：播放選單提供 15 / 30 / 60 / 90 分鐘、本集播完、再播完 3 / 5 集。按實際經過時間計時，暫停也計時；按集數僅在片尾計數，手動切集不扣次數。片尾先判斷停止，再決定是否自動下一集。到點暫停、儲存進度、取消自動恢復，釋放保持亮屏；按播放可繼續。僅本次觀看有效，退出播放器或切到後臺取消。
- 手機備份與恢復：設定中顯示同一區域網二維碼，瀏覽器下載或上傳本原生版 JSON 備份，包含收藏、觀看進度、已看標記、搜尋歷史和全域性設定。上傳不直接寫入，電視展示數量、預設聚焦取消，確認才合併。已有收藏優先，進度按時間保留較新記錄；預設不覆蓋全域性設定，勾選後才恢復。最多 500 部收藏、200 條最近觀看、20 條搜尋；2 MB 檔案限制。
- 全域性畫面模式：完整畫面（預設）、等比鋪滿、拉伸鋪滿，播放中立即切換並持久化，選擇時說明裁切字幕或改變比例的影響。
- 系統媒體控制：前臺播放器釋出劇名、集數、時長、位置和狀態，回應播放、暫停、上下集、定位和停止。後臺會話停用，不增加後臺播放服務。影片載入期間收到的暫停不會被後續載入覆蓋；選集面板中暫停後，取消面板不會誤播放，播放按鈕同步顯示實際狀態。

備份 HTTP 視窗使用隨機 128 位地址，最長 5 分鐘；檢查 Host、Origin、路徑、請求大小和 JSON 結構，限制連線讀取時長，關閉視窗/進入後臺終止監聽和在途連線。每個二維碼僅下載一次，成功上傳後關閉會話，仍需電視確認。檔案不包含平臺登入憑據，也不提供紅果帳號同步。

### 驗證

- 50 項 JVM 測試全部透過；正式 Release 構建、lint 透過（0 error / 23 warning，主要為依賴更新提示、已有平臺屬性與文字本地化提示）。新增測試覆蓋定時到點/片尾/取消/切換，備份合併新舊進度和上限，錯誤格式/重複記錄/深層 JSON，HTTP 單次傳輸、來源校驗、超限拒絕、超時及關閉。
- Android TV API 36 ARM64 模擬器覆蓋安裝正式 APK，保留已有收藏和進度。透過遙控器驗證播放選單、三種畫面選項、定時選擇、片尾停止攔截下一集、系統媒體播放/暫停/上下集/停止、切集立即暫停、選集面板暫停後取消、退後臺會話停用和取消定時。
- 正式 APK 真實 HTTP 匯出再匯入測試資料，驗證電視取消不寫入、合併較新進度、預設保留設定、勾選後恢復設定及重啟保留。傳輸透過模擬器網路轉發完成；真實手機掃碼、路由器隔離策略和不同手機瀏覽器尚未驗收。
- 預設 1080p 與 720p / 1.5 倍字型截圖檢查，新按鈕和彈窗可透過方向鍵到達。按分鐘的到點邊界透過注入單調時鐘的核心測試驗證，沒有聲稱連續等待了 90 分鐘；安裝包實際驗證片尾定時停止。
- 迴歸發現並修正 JVM JSON 與 Android JSON 浮點過載差異；未將早期匯出失敗當作透過證據。驗證包記錄各批截圖對應的 APK 雜湊，最終 APK 複測播放、定時和匯入匯出主鏈路。另修復了短暫退後臺後定時按鈕仍顯示舊倒計時的問題。

Android 8.0 實體電視解碼、音訊、實體藍芽遙控器及長期穩定性仍需實機驗收。紅果/抖音授權與平臺收藏進度同步仍未接通；本輪備份是本機資料遷移。

# Kotlin TV 0.4.0

基於遠端 `7d76463`，包名 `com.hongguotv.nativeapp`，versionCode 4，最低 Android 8.0 / API 26。仍為獨立 APK，無需 Docker 或另外部署服務。

### 功能

- 播放故障恢復：臨時網路/資源讀取錯誤最多自動重試 3 次，間隔 1 / 2.5 / 5 秒；沒有可用網路時等待網路恢復，不消耗次數。重新請求播放地址，保留集數、位置和播放/暫停意圖。提供立即重試、停止自動重試、720P 與返回選集；離開前臺取消自動重試。解碼錯誤不反覆發起網路重試，並啟用裝置可用解碼器初始化回退。
- 播放中選集：側邊面板預設聚焦當前集，每組 20 集，支援數字定位、首末組禁用和方向鍵導航；確認新集才換集，取消恢復原播放狀態和焦點。開啟面板臨時暫停，不退出播放器。
- 首頁一鍵續播：顯示最近 3 部沒有手動標記整劇已看的劇；按劇集 ID 匹配最新列表，已播完當前集則進入下一集。源列表移除原集時從首集開始，已到最後一集時從末集開頭開始。推薦載入不阻塞本機續播入口。
- 收藏劇更新提示：前臺啟動檢查超過一小時未檢查的收藏，可手動重新整理。首次建立基準，此後顯示新增集數與當前總集數；進入詳情後確認已檢視。檢查失敗保留舊結果，序列請求，單請求 12 秒，連續 3 部失敗停止本輪檢查。應用退後臺後不再啟動後續檢查；已在途請求可能執行到超時。無後臺推送，不是紅果帳號同步。
- 全域性預設清晰度與倍速：設定提供 480P / 720P / 1080P、0.75 / 1 / 1.25 / 1.5 / 1.75 / 2×，沿用舊設定並持久化。清晰度按片源可用檔位選擇；播放中修改會儲存為全域性預設，切清晰度保留位置與暫停狀態。

### 驗證與邊界

- 正式簽名構建、40 項 JVM 測試透過；Release lint 0 error / 19 warning。核心測試覆蓋續播 ID 重排/缺失/末集、有限重試、配置相容、收藏首次基準/累計新增/確認/回退/過期回應/損壞資料。
- Android TV API 36 ARM64 模擬器，預設 1080p 與 720p / 1.5 倍字型；方向鍵開啟側邊選集，定位並選擇第 788 集，檢查末組邊界與取消焦點。首頁直接進入播放，全域性配置跨重啟保留。
- 使用模擬器系統提供的單應用網路阻止功能製造真實 SocketTimeoutException。發現並修復恢復聯網權限後不自動重試的問題，補充網路阻止狀態回呼；修復後記錄 `Automatic playback recovery 1/3 at 7751ms`，恢復到相同的 00:07 暫停位置，480P / 1.5×。測試後還原系統網路配置。
- 收藏新增場景使用明確的合成舊基準 785 集，正式 APK 從真實介面讀取 788 集，展示新增 3 集；重啟保留，進入詳情後清除。它證明檢測鏈路，不聲稱測試期間平臺實際釋出了三集。臨時開發包只用於寫入模擬器測試基準，觀察前恢復正式 APK，開發包不交付。原測試記錄在結束時恢復。
- 大字號截圖檢查發現收藏卡片的總集數被省略，最終 APK 將收藏更新說明改為兩行，並重新驗證完整顯示。驗證包包含功能測試版本及最終文字換行修復版本的明確 APK 雜湊對應關係；不會將中間失敗記錄當作透過證據。
- 記錄的 UI XML 可透過 `python3 tools/verify-watching-evidence.py <tv目录>` 複核；這不是自動驅動遙控器的測試，也不替代截圖目視檢查。

尚未驗收 Android 8.0 實體電視解碼/音訊、長時間穩定性及各品牌系統差異。網路恢復的真實注入覆蓋已暫停場景；三次上限由核心測試及呼叫路徑檢查驗證。帳號登入和平臺同步仍未接通。
